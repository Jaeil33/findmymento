## 작업

### 1. 회차 목록과 생성 — UC-01

```ts
type SessionDraft = {
  title: string
  field: string               // 5개 분야 중 하나
  heldOn: string              // 특강 날짜
  closesAt: string            // 응답 마감 (E-17)
  instructorId: string | null // 배정 강사 (ADR-015)
}
```

**배정 강사 지정이 이 화면의 새 책임이다 (UC-01).**

- 승인된(`approved`) 강사만 후보로 보여준다. 해당 분야 강사를 먼저 정렬한다.
- `instructorId`는 nullable이지만 **비워두면 그 강사는 교실 QR 화면도 회차 리포트도 볼 수 없다** (UC-28·29). 강사 구독의 가치가 거기서 나오므로 폼에서 강하게 유도하고, 목록에서 **미배정 회차를 눈에 띄게 표시**한다 (E-23).
- 배정을 필수 입력으로 만들지는 마라. 외부 강사가 확정되지 않은 상태로 회차를 먼저 등록하는 일이 실제로 있다.

- 생성 시 **입장 코드 6자리**를 발급한다. 사람이 읽고 손으로 입력하는 코드다 — 혼동되는 문자(`0`/`O`, `1`/`I`/`l`)를 제외한 문자 집합을 쓴다.
- 입장 코드는 전역 유니크. 충돌 시 재생성한다.
- `closesAt` 기본값은 특강 날짜 + 3일을 제안하되 수정 가능하게 한다.
- 목록에서 회차를 **열기/닫기**할 수 있다. 닫힌 회차의 설문 제출은 거부된다(E-17).

**UC-27 — 후속 과정도 그냥 새 회차로 등록한다.** 부모-자식 링크 필드를 만들지 마라. 루프는 데이터 구조가 아니라 운영 행위다. 스키마를 건드리지 않는다.

### 2. QR 출력 — UC-01

- QR은 `qrcode` npm 패키지로 **서버에서 SVG를 생성**한다. 외부 QR 생성 API나 CDN 이미지를 쓰지 마라(CSP·가용성·개인정보 모두 문제).
- QR이 가리키는 URL은 `{배포 도메인}/s/{입장코드}`다. 도메인은 환경변수에서 읽는다 — 하드코딩하지 마라.
- 인쇄용 화면을 따로 둔다: QR 크게 + 입장 코드 숫자 크게 + 한 줄 안내. 교실 프로젝터에 띄우거나 A4로 출력해 붙이는 용도다.
- **안내 문구를 "만족도 조사"로 쓰지 마라.** 학생이 찍을 이유는 본인 이득이다 — `QR을 찍으면 나에게 맞는 다음 교육을 찾아줘요` 쪽으로 쓴다 (SURVEY.md 설계 원칙 7, UI_GUIDE 안전 규칙 8).
- 이 투사용 화면은 **step 12에서 강사 화면이 재사용한다** (UC-28). 컴포넌트를 `(org)` 전용 디렉토리에 묶어두지 말고 `components/`에 두어라.

### 3. 학생 가명코드 일괄 발급 — UC-02 (H1의 직접 원인)

```ts
export async function issuePseudoCodes(orgId: string, count: number): Promise<string[]>
```

**반드시 지킬 것 — 가명코드는 난수여야 한다.**

순번(`A001`, `A002`…)으로 발급하지 마라. 순번이면 한 학생이 자기 코드에서 다른 학생의 코드를 추측해 그 학생의 응답 이력을 열 수 있다. 가명코드는 **추측 불가능한 난수**여야 하고, 그래서 가명 처리가 성립한다.

- 기관 단위로 유니크. 충돌 시 재생성.
- 혼동 문자 제외, 6~8자.
- 발급 이력을 남긴다 — 몇 개를 언제 발급했는지 기관이 확인할 수 있어야 한다.

### 4. 가명코드 인쇄 화면 — UC-02

배부 가능한 형태로 출력한다.

- A4 기준 그리드(가로 4 × 세로 8 정도), 가위로 자르거나 접어 나눠줄 수 있는 카드.
- 카드 1장에 들어가는 것: **가명코드만.** 학생 이름 칸을 인쇄물에 만들지 마라 — 기관이 손으로 매핑표를 관리하는 것은 기관의 일이고, 플랫폼이 이름을 다루는 순간 설계 전제가 깨진다.
- `@media print` 로 화면 UI(네비게이션·버튼)를 숨기고 잉크 절약 스타일을 적용한다.

### 5. 회차 상세

해당 회차의 응답 수만 가볍게 보여준다. **익명 응답 수를 따로 표시한다**(E-04) — 한 기기를 돌려 쓴 경우를 기관이 판단할 수 있어야 한다.

집계·리포트의 본체는 step 11이다. 여기서는 숫자 2개(총 응답, 익명 응답)까지.

### 6. 테스트 (TDD — 먼저 작성)

1. 회차 생성 시 입장 코드가 6자리이고 혼동 문자(`0O1Il`)를 포함하지 않는다
2. 입장 코드 충돌 시 재발급된다
3. **가명코드가 순차적이지 않다** — 100개 발급 후 연속 증가 패턴이 없음을 통계적으로 확인
4. 가명코드가 기관 내 유니크하다
5. 닫힌 회차는 설문 제출이 거부된다 (E-17)
6. QR SVG가 `/s/{입장코드}`를 인코딩한다
7. 기관 A 담당자가 기관 B의 회차 목록을 조회하면 0건 (RLS)
8. 인쇄 화면에 학생 이름 입력란이 존재하지 않는다
9. 회차 상세에 익명 응답 수가 별도로 표시된다 (E-04)

## 금지사항

- 가명코드를 순번으로 발급하지 마라. 이유: 한 학생이 다른 학생의 코드를 추측해 응답 이력을 볼 수 있다. 추측 가능한 코드는 가명 처리가 아니다.
- 인쇄물·화면에 학생 이름 필드를 만들지 마라. 이유: 코드↔실명 매핑은 기관만 보유한다(ADR-003). 플랫폼이 이름을 한 번이라도 다루면 수탁자 구조가 깨진다.
- 외부 QR 생성 API·CDN 이미지를 쓰지 마라. 이유: 입장 코드가 외부 서비스 로그에 남고, 그 서비스가 죽으면 교실에서 QR이 안 뜬다.
- QR URL에 도메인을 하드코딩하지 마라. 이유: 배포는 마지막 step이다(ADR-012). 하드코딩하면 배포 후 모든 QR을 다시 출력해야 한다.
- 후속 과정을 위한 부모-자식 링크 컬럼을 추가하지 마라. 이유: 스키마는 step 2에서 확정됐다. 루프는 새 회차를 만드는 운영 행위로 충분하다.
- 리포트·집계 화면을 만들지 마라. 이유: step 11의 작업이다.
- 기존 테스트를 깨뜨리지 마라.
