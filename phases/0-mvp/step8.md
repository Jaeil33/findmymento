## 작업

### 1. 추천 결과 화면

설문 제출 직후 도달하는 화면. 구성은 3가지뿐이다.

1. 한 줄 요약 — "○○에 관심이 있다고 했으니, 이런 걸 더 배워볼 수 있어요"
2. 추천 카드 3~5장 — `Card variant="student"`
3. 다음 행동 — 카드별 "더 배워보고 싶어요" 버튼

추천 카드에 담는 것: 강사명, 소속 업체명, 분야, 프로그램 제목, 지역(시군구명), **추천 이유 한 줄**. 같은 카드 구성을 step 14의 공개 디렉토리가 재사용하므로 `components/`에 둔다 (행동 버튼만 다르다 — 학생은 "더 배우고 싶어요", 보호자는 "문의하기").

**담지 않는 것: 연락처, 이메일, SNS, 주소, 강사 개인 사진.** 조건부로 숨기는 컴포넌트도 만들지 마라. 영역 자체가 없어야 한다(UI_GUIDE 안전 규칙 1·4).

### 2. 로딩 상태

추천 생성에 1~3초가 걸린다. **스피너를 쓰지 말고 정적 문구**("추천을 찾고 있어요")로 처리한다(UI_GUIDE 애니메이션 규칙).

### 3. 관심 표현

```ts
// src/app/api/interests/route.ts
type InterestSubmission = { sessionCode: string; pseudoCode: string | null; targetType: "program" | "instructor"; targetId: string }
```

- `interests`에 기록하고 상태는 기관 검토 대기로 둔다.
- **멱등성** — 같은 학생이 같은 대상에 두 번 누르면 행이 하나만 생긴다.
- 기록 후 안내 문구: **"선생님이 확인한 뒤 알려줄 거예요."** 학생이 강사에게 직접 연락이 갈 것처럼 기대하게 만드는 문구를 쓰지 마라.
- 익명 응답 학생도 관심 표현은 가능하게 한다. 단 기관이 누구인지 특정할 수 없다는 점을 기관 화면에서 구분해 보여줄 수 있도록 `student_id`를 NULL로 남긴다.

### 4. 후보 0건 화면

추천이 0건인 경우가 파일럿에서 **과반**일 수 있다(공급이 2개 분야뿐이다). 이 화면을 성의 있게 만들어라.

- "광명시에 아직 이 분야 강사가 없어요"를 솔직하게 알린다.
- **Q&A로 먼저 물어보기** CTA를 가장 크게 둔다. 이게 관심 신호를 잃지 않는 유일한 경로다.
- "수요가 모이면 선생님이 강사를 찾아볼 거예요" 안내로 닫는다. 거짓 약속을 하지 마라.

### 5. 테스트 (TDD — 먼저 작성)

1. 추천 3건이 주어지면 카드 3장이 렌더된다
2. **렌더된 DOM과 API 응답 어디에도 전화번호·이메일 형태 문자열이 없다**
3. 후보 0건 응답 → Q&A CTA가 렌더된다
4. 같은 학생이 같은 대상에 관심 표현 2회 → `interests` 행이 1개
5. 익명 학생의 관심 표현이 `student_id: null`로 저장된다
6. 로딩 중 스피너 컴포넌트가 없다 (정적 문구)
7. 버튼 터치 타깃이 48px 이상이다

   - UI_GUIDE 안전 규칙 5개를 지키는가?

   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 연락처를 표시하는 UI 영역을 만들지 마라. 조건부 숨김도 안 된다. 이유: 존재하지 않는 영역은 새지 않는다. 조건문 하나가 잘못되면 미성년자에게 성인 강사 연락처가 노출된다(UI_GUIDE 안전 규칙 1).
- 강사 개인 사진을 쓰지 마라. 이유: UI_GUIDE 안전 규칙 4.
- "강사에게 문의하기" 같은 직접 연결 문구를 쓰지 마라. 이유: 연결은 항상 기관을 경유한다(CLAUDE.md). 학생이 직접 연락을 기대하게 만들면 그 기대를 채워주는 기능을 누군가 만들게 된다. **문의 기능 자체는 존재하지만(step 14) 그건 공개 디렉토리에서 성인 보호자가 쓰는 것이고, 학생 추천 화면에는 그 버튼을 두지 않는다** (ADR-014).
- 후보 0건 화면을 빈 화면이나 에러처럼 보이게 만들지 마라. 이유: 파일럿에서 이 화면을 보는 학생이 과반일 수 있고, 이 화면의 품질이 Q&A 전환율을 결정한다.
- 스피너·로딩 애니메이션을 추가하지 마라. 이유: UI_GUIDE 애니메이션 허용 목록에 없다.
- 기존 테스트를 깨뜨리지 마라.
