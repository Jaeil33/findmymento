## 이 phase 전체의 배경

지금 AI는 수업 **전**(기관 회차 기획 — ADR-021, 강사 교안 — ADR-017)과 **직후**(학생 추천 — ADR-004)에만 있다. 수업이 끝난 **후** 기관 담당자와 강사가 손으로 하는 일에는 AI가 없다.

- 기관 담당자: 회차 결과보고서 작성, 후속 과정을 열지 판단하고 강사에게 섭외 문안 작성
- 강사: 수업 회고, 학교·기관에 제출할 수업 결과 요약

조사(`research.md`) 결론: 교과 교사용 AI(생기부 초안·평가 문항·학생 개인 맞춤)는 이미 포화이고 규제도 거기에 집중돼 있다. 반면 **외부 직업인 강사가 진행한 1회성 특강의 회차 후 요약·결과보고·후속 프로그램 제안**을 돕는 AI는 공백이다. 이 phase는 그 공백에 AI 기능 3개를 넣는다.

| # | 기능 | 사용자 | API | 과금 근거 |
|---|---|---|---|---|
| 4 | 결과보고서 초안 | 발주 기관·학교 구성원 | `POST /api/result-report` | 기관 — 보고 업무 대체 |
| 5 | 후속 과정 제안 + 섭외 요청 문안 | 발주 기관·학교 구성원 | `POST /api/followup-plan` | 기관 — 다음 섭외로 이어짐 (주 지표) |
| 6 | 수업 회고 + 학교 제출용 결과 요약 | 배정 강사 | `POST /api/session-debrief` | 강사 — 리포트의 가치 |

세 기능 공통 설계 (이후 step 이 전부 이 문서를 가드레일로 받는다):

1. **아무것도 저장하지 않는다.** 초안을 생성해 화면에 보여주고 복사할 수 있게 할 뿐이다. 새 테이블·새 RLS 정책이 없다.
2. **숫자·후보·사실은 규칙이 확정하고 LLM은 문장만 쓴다** (ADR-004/017/021과 같은 하이브리드). LLM이 실패하면 규칙 초안으로 200을 반환한다.
3. **응답 5건 미만 회차는 만족도·후속 의향·관심 분야·학생 의견을 싣지 않고 LLM도 부르지 않는다** (ADR-018의 k-익명성 임계치를 수업 후 AI에도 적용).
4. **숫자 가드**: LLM 문장에 규칙이 주지 않은 숫자가 있으면 그 문장을 버린다 (환각 수치 차단).
5. **이름 가드**: LLM 문장에 강사명·기관명·업체명이 들어가면 버린다. 연락처·링크는 `maskForStorage`로 거른다.
6. **학생 개인을 지목·평가하는 문장을 만들지 않는다.** 단위는 회차다.
7. 결과보고서의 **창체 진로활동 기록 참고 문구**는 회차 단위 활동 서술 한 문장이며, 2026 학교생활기록부 기재요령에 따라 강사명·기관명·상호명을 넣지 않고 "AI 문장을 그대로 입력하지 말 것 / 학교가 주최·주관한 활동에만 기재 가능"을 화면에 고지한다. 학생 개인별 특기사항 문장은 만들지 않는다 (영구).
8. 후속 과정 제안은 **모집·정원·수강료·신청 폼을 다루지 않는다** (ADR-023). 강사 후보는 규칙이 고르며 정렬은 거리·이름뿐이고 소속 업체·구독·결제 여부를 반영하지 않는다 (ADR-009). 섭외 요청을 자동 발송하지 않는다 — 기관이 기존 섭외 화면에서 직접 보낸다.
9. 권한: 기능 4·5는 `org_member`이면서 **자기 기관의 회차**일 때만, 기능 6은 `instructor`이면서 **그 회차의 배정 강사**일 때만. 역할이 틀리면 403, 회차가 없거나 남의 회차면 404 (존재 여부를 구분해 흘리지 않는다).

화면 버튼 문구 (step 6 이 그대로 쓴다): `결과보고서 초안 만들기`, `후속 과정 제안받기`, `수업 회고 만들기`.

### 1. `docs/AI.md`

- 상단 "관련 결정" 줄에 ADR-024 추가.
- "AI 기능 3 — 회차 기획 도우미" 절 뒤에 `## 수업 후 AI — 기능 4·5·6 (ADR-024)` 절을 추가한다. 기능마다 기존 형식(언제 / 누구 / 무엇 / 입력 / 출력 / 규칙과 LLM의 분담)을 따른다.
  - 기능 4 결과보고서 초안: 출력 섹션 = 제목, 운영 개요(일시·장소·대상·예상 인원·시수·분야·배정 강사), 지표(응답 수·응답률·만족도 평균·후속 의향 3점 이상 수와 비율·관심 분야 상위), 성과 요약, 학생 의견 요약, 개선점, 후속 계획, 창체 기록 참고 문구, 고지문. 운영 개요·지표·고지문은 규칙, 나머지 문장은 LLM(실패 시 규칙 문장).
  - 기능 5 후속 과정 제안: 입력 = 후속 의향 3점 이상 응답의 관심 분야 1위·참여 가능 시간 1위(집계), 기관 지역 기준 같은 시군구→인접→2-hop 승인 강사. 출력 = 분야, 관심 응답 수, 권장 시간대, 과정 제목, 차시 구성(기본 4차시), 강사 후보(최대 3, 규칙), 섭외 요청 문안, 고지문. 관내·인접에 공급이 없으면 후보 없이 "미충족 수요"로 안내한다.
  - 기능 6 수업 회고: 입력 = 배정 회차 집계(+ 그 회차 교안이 있으면 단계 제목). 출력 = 잘 된 점(최대 3), 다음에 바꿀 점(최대 3), 학교 제출용 결과 요약(400자 이내), 고지문. 규칙 트리거 예: 후속 의향 3점 이상 비율 40% 미만 → 마무리 안내 강화 제안(USER_FLOW H2 임계치), 만족도 1·2점 비율 20% 이상 → 난이도 분기 점검, 관심 분야 1위가 회차 분야와 다름 → 연계 직업 소개, 응답률 50% 미만 → QR 안내 시점 제안.
- "그냥 ChatGPT에 물어보면 되지 않나" 절에 한 문단 추가: 수업 후 AI는 그 회차의 집계를 이미 갖고 있으므로 담당자가 설문을 엑셀로 옮기고 요약하는 일이 사라진다.
- "안전 경계" 표에 행 추가: 숫자 가드, 이름 가드, 저장하지 않음, 수업 후 AI의 5건 임계치, 창체 기록 참고 문구 규칙, 후속 제안의 모집·정원·수강료 금지.
- "실패해도 화면은 뜬다" 표에 3행 추가.
- "비용" 표에 3행 추가 (각 호출당 약 50원 수준 — 추정이라고 적는다).
- "만들지 않는 것"에 추가: 학생 개인별 생기부 특기사항 문장(영구), NEIS 입력·공문 자동 제출, 섭외 요청 자동 발송, 강사 평점·순위.
- "구현 체크리스트"에 `기능 4~6 — 수업 후 AI: 구현 예정` 섹션과 네거티브 테스트 목록(체크 안 된 상태)을 추가한다. 네거티브 테스트: 타 기관 404 / 강사가 기관 라우트 호출 403 / 미배정 강사 404 / 응답 4건 회차에서 통계·의견·LLM 호출 없음 / 규칙에 없는 숫자가 든 LLM 문장 폐기 / 강사명·기관명 든 문장 폐기 / 응답에 연락처 없음 / 후보를 LLM이 늘릴 수 없음 / 키 없이 200.

### 2. `docs/ADR.md`

파일 끝에 기존 형식(`### ADR-0xx: 제목` / `**결정**` / `**이유**` / `**트레이드오프**`)으로 추가한다.

`### ADR-024: 수업 후 AI 3종 — 결과보고서·후속 과정 제안·수업 회고. 저장하지 않고, 숫자는 규칙이 확정한다`

- 결정: 위 "공통 설계" 1~9를 결정문으로 쓴다.
- 이유: AI가 돈 내는 쪽의 수업 후 노동에 없었다 / 조사 근거(research.md의 반복 문서 작업 Top 5 중 5번, 시장 공백) / 결과보고서는 ADR-021이 말한 "리포트는 있으면 좋은 것"을 "결재 문서에 적을 이유"로 바꾼다 / 후속 제안은 주 지표(기관의 섭외 요청 발송)로 곧장 이어진다.
- 트레이드오프: 저장하지 않으므로 생성 이력으로 품질을 추적할 수 없다(검수는 source 로그로만) / 숫자 가드가 정상 문장도 버릴 수 있다(그때는 규칙 문장이 나온다) / 창체 참고 문구는 규제가 강화되면 제거할 수 있게 한 필드로만 둔다.

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 체크리스트:
   - 기존 ADR(특히 ADR-003·009·016~023)의 결정 내용을 바꾸거나 약화하지 않았는가?
   - CLAUDE.md CRITICAL 규칙과 충돌하는 기능 설명을 쓰지 않았는가? (학생 개인 진단·학생 주체 연결·모집·수납·1:1 메시지)
   - `docs/AI_RESEARCH.md`의 모든 수치·주장에 research.md의 출처가 있는가?
3. 결과에 따라 `phases/1-post-session-ai/index.json`의 step 0을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"` (수정한 문서 목록과 ADR 번호, 버튼 문구를 담는다)
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

- `src/`, `tests/`, `supabase/`, `scripts/` 아래 파일을 수정하지 마라. 이유: 이 step은 이후 step의 가드레일이 될 스펙만 쓴다.
