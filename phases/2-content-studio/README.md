# Phase 2 — 콘텐츠 스튜디오

제품의 중심을 강사 매칭에서 **실습 콘텐츠 제작·검증·운영**으로 옮긴다 (ADR-028).
제약 조건과 검증 항목의 유일한 출처는 `docs/STUDIO.md`이고, 임계값의 유일한 출처는
`src/lib/studio/constants.ts`다. 둘이 어긋나면 테스트가 터지게 둔다.

## 순서와 이유

| # | step | 무엇을 만드나 | 왜 이 순서인가 |
|---|---|---|---|
| 0 | `studio-constants` | 타입 + 물리 상수 + 상수↔문서 일치 테스트 | 임계값이 흩어지면 "통과시키려고 낮추는" 사고가 난다 |
| 1 | `studio-geometry` | mm 단위 기하 연산 (길이·bbox·선분 최단거리·내각·닫힘·배치) | 검증기의 전부가 여기서 나온다 |
| 2 | `pen3d-recipes` | 파라메트릭 레시피 — 부품·접합을 결정론적으로 생성 | LLM이 좌표를 만들지 않는다 (ADR-029) |
| 3 | `pen3d-validate` | 14개 검증 항목 | 생성보다 검증이 먼저 옳아야 한다 |
| 4 | `pen3d-pipeline` | 생성 → 검증 → 개선 → 재검증 (최대 3회) + 라운드 기록 | ADR-030 |
| 5 | `pen3d-render` | A4 1:1 SVG (mm, 실선 윤곽 / 파선 굽힘) | 축척이 틀리면 전부 무의미하다 |
| 6 | `studio-db` | `studio_contents`·`studio_feedback` + RLS + 네거티브 테스트 | 소유 경계가 코드보다 먼저 DB에 있어야 한다 (ADR-031) |
| 7 | `studio-api` | `/api/studio/*` + LLM 레시피 선택·문장 (실패 시 규칙) | 키는 서버 전용 |
| 8 | `studio-ui` | 스튜디오 라이브러리·생성·검증 결과·승인 화면 | |
| 9 | `studio-feedback` | 회차 단위 성과 입력 + 3건 이상일 때 상수 보정 | ADR-032 |
| 10 | `drone-mission` | 비행 미션 생성 + 시뮬레이터 + 12개 검증 항목 | 3D펜에서 검증된 파이프라인을 재사용 |
| 11 | `drone-ui` | 스튜디오에 드론 추가 + 코드 내려받기 | |

## 전 step 공통 금지사항

- LLM에게 좌표·치수·비행 명령을 만들게 하지 마라. 이유: 검증할 수 없는 숫자가 들어온다 (ADR-029)
- 임계값을 완화해 테스트를 통과시키지 마라. 이유: 임계값은 물리 현상이다. 생성기를 고쳐라
- 기존 매칭 화면의 테스트를 깨지 마라. 이유: 매칭은 유지 대상이다 (ADR-028)
- 목업·하드코딩된 가짜 산출물을 넣지 마라. 이유: 검증기가 통과시킨 산출물만 화면에 나와야 한다

## 도안 실물 확인

`tests/studio-sample.manual.test.ts` 는 `STUDIO_SAMPLE_DIR` 가 있을 때만 돌고, 레시피별 SVG 와
지표 표를 그 디렉토리에 쓴다. 숫자만 보고 통과시키지 말고 **A4 로 인쇄해서** 50mm 기준선을
자로 재 보는 것이 최종 확인이다.

```bash
STUDIO_SAMPLE_DIR=/tmp/svg npx vitest run tests/studio-sample.manual.test.ts
```
