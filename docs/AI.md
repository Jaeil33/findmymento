# AI 설계

Find My Mento에서 AI가 어디에 있고, 왜 거기에 있는가. 이 문서 하나로 설명이 끝나야 한다.

관련 결정: ADR-004(학생 추천), ADR-016(학급 특성), ADR-017(수업 설계 도우미), ADR-018(과거 설문 입력), ADR-019(교안 소유), ADR-021(회차 기획 도우미).

---

## 원칙 한 줄

> **연결이 제품이고, AI는 그 연결을 실행 가능하게 만드는 공급자 도구다.**

학생에게 가는 AI는 QR을 찍을 이유 한 줄까지다. 그 이상의 AI는 전부 강사·기관 쪽으로 간다. 이유는 두 개다.

1. **돈을 내는 쪽의 노동을 줄여야 구독이 성립한다.** 학생과 보호자에게는 과금하지 않는다.
2. **학생 데이터를 늘리지 않아야 가명코드 설계가 유지된다.** 학생에게 더 똑똑한 AI를 주려면 학생을 더 많이 알아야 하는데, 이 서비스는 학생을 알지 않기로 하고 시작했다 (ADR-003).

## 어떻게 여기까지 왔는가

| | 1차 구상 | 2차 구상 | 현재 |
|---|---|---|---|
| AI의 역할 | 제품 그 자체 | QR을 찍을 이유 | 공급자의 실행 도구 |
| 개인화 단위 | 학생 한 명 | — | **학급 한 반** |
| 수혜자 | 학생 | 학생 | **강사·기관** |
| 첫 수업에서 | 데이터 0 — 작동 안 함 | 작동 | 작동 |

1차에서는 학생의 활동 데이터(미션 성공 여부, 수행 시간, 모델링 결과)를 쌓아 개인별 다음 활동과 난이도를 추천하려 했다. 두 가지가 걸렸다. **첫 수업 첫 학생에게는 데이터가 0이고**, 데이터를 모으려면 미성년자 개인 기록을 축적해야 한다.

2차에서는 AI를 제품의 중심에서 내리고 연결을 제품으로 삼았다. 문제 정의는 맞았지만 AI가 학생 화면 한 곳에만 남았다 — **돈을 내지 않는 쪽에만.**

현재는 개인화를 버리지 않고 **단위를 올렸다.**

| | 학생 한 명 단위 | 학급 한 반 단위 |
|---|---|---|
| 필요한 데이터 | 개인별 활동 이력 축적 | 기관이 이미 아는 회차 조건 |
| 첫 수업에서 | 작동하지 않음 | 즉시 작동 |
| 미성년자 정보 | 개인 기록을 쌓아야 함 | 학생을 식별하지 않음 |
| 수혜자 | 과금하지 않는 학생 | 구독료를 내는 강사·기관 |

한 칸을 옮기자 콜드스타트와 미성년자 데이터 문제가 동시에 사라졌다.

## AI 기능 1 — 학생 추천 (기존)

**언제**: 특강 마지막 3분, 설문 제출 직후
**누구**: 학생 (로그인 없음)
**무엇**: 우리 지역에서 다음에 들을 수 있는 교육 카드 3~5장 + 추천 이유 한 줄

```
규칙 필터 (SQL)           LLM
────────────────          ──────────────
지역 (시군구→인접→2-hop)   후보 안에서 순위
대상 학년                  이유 한 줄 (50자, 존댓말)
관심 분야
강사 승인 상태
   ↓                         ↓
후보 확정 ──────────────→ 순위 + 문구
```

**LLM은 후보를 새로 만들 수 없다.** 존재하지 않는 강사를 추천하는 환각이 구조적으로 불가능하다. 구현은 `src/lib/ai/recommend.ts`.

이 기능은 **더 키우지 않는다.** 학생별 수준 진단, 개인 학습경로, 장기 프로필은 만들지 않는다.

## AI 기능 2 — 수업 설계 도우미 (신규)

**언제**: 회차 배정 후, 수업 전
**누구**: 배정된 강사
**무엇**: 이 반 조건에 맞춘 교안 초안 — 차시 흐름 + 단계별 난이도 분기

### 입력

```
① 회차 조건        기관이 회차를 만들 때 입력 (ADR-016)
   시수 · 장소 · 예상 인원 · 학급 특성 · 보유 장비

② 강사 프로그램     이미 등록돼 있는 outline
   "드론 조종 기초 3차시" 의 차시 구성

③ 지난 회차 설문     같은 기관 + 같은 분야, 응답 5건 이상일 때만 (ADR-018)
   만족도 · 후속 의향 · 관심 분야 분포 · 자유서술에서 반복된 표현
```

③이 이 제품의 전부다. ①②는 잘 만든 폼이고, ③은 **우리만 가진 것**이다.

### 출력

```
[전개 2단계] 드론 자율비행 코딩 (15분)
  기본        블록 3개로 사각형 경로 만들기
  빨리 끝남    장애물 회피 조건 추가
  어려워함     경로를 2개 블록으로 줄이고 교사가 1개 시범
  통합학급     짝 활동으로 전환, 조종 담당 / 코딩 담당 분리
```

마지막 줄은 그 회차에 해당 조건이 있을 때만 생성된다. 강사가 가장 자주 포기하는 부분이 **진도 편차 대응**이고, 그게 여기 있다.

산출물 범위는 **차시 흐름 + 난이도 조절안까지**다. 학생 활동지와 학교 제출용 계획서 서식은 만들지 않는다.

## AI 기능 3 — 회차 기획 도우미 (기관·학교용)

**언제**: 회차를 만들기 전
**누구**: 기관·학교 담당자
**무엇**: 어떤 특강을 열어야 하는지의 초안

### 입력

```
① 담당자가 입력     대상 학년 · 인원 · 시수 · 목적 · 예산대
② 시스템이 이미 앎   우리 지역 강사·프로그램 공급 현황
③ 시스템이 이미 앎   관내 미충족 수요 집계 (공급 없음 / 장소 없음)
```

### 출력

```
제안  중2 자유학기 주제선택 · 25명 · 2시간
      → 드론 조종 입문 2차시가 맞습니다. 관내 공급 3곳.
      → 강사에게 요구할 것: 기체 10대 이상 지참, 실내 비행 가능 기체
      → 사전 준비물: 강당 또는 체육관, 전원 2구
참고  관내 VR 관심 14명 · 공급 0 — 지금은 열 수 없지만 예산 기안의 근거가 됩니다
```

후보 분야와 강사 요건은 **규칙**이 확정한다. LLM은 문장만 만든다. 존재하지 않는 공급을 제안하는 일이 구조적으로 불가능하다.

**왜 이걸 만드나**: 담당 선생님의 현재 대안은 꿈길도 크레존도 아니다. **작년 파일을 열어 작년 업체에 전화하는 것**이다. 비용 0 · 학습 0 · 리스크 0인 이 선택을 이기려면 더 좋은 강사를 보여주는 것으로는 부족하고 **지금 하는 일을 줄여야** 한다. 기관 과금의 근거가 여기서 나온다 (ADR-021).

## "그냥 ChatGPT에 물어보면 되지 않나"

심사에서 반드시 나오는 질문이고, 답은 하나뿐이다.

> **범용 모델은 이 학교 학생들이 지난번에 조종보다 조립에 반응했다는 사실을 모른다. 우리는 그 데이터를 갖고 있다 — 학생이 특강 직후 찍은 QR에서 나왔다.**

```
특강 → QR → 설문 → 추천 카드 (학생)
                 ↓
              설문 집계
                 ↓
        다음 회차 교안 초안 (강사)
                 ↓
              다음 특강 → QR → 설문 → …
```

루프가 여기서 닫힌다. **회차가 쌓일수록 교안이 좋아지는 구조**이고, 이것이 우리 데이터가 제품을 개선하는 첫 경로다. 프롬프트는 복제할 수 있지만 그 교실에서 나온 응답은 복제할 수 없다.

부수적인 답 둘:

- **입력이 이미 시스템에 있다.** 강사는 회차 조건을 다시 적지 않는다. 프롬프트를 쓰는 것 자체가 장벽인 40~60대 현장 강사에게는 이쪽이 더 실질적이다.
- **안전·접근성 규칙이 제품에 박혀 있다.** 범용 챗봇은 "휠체어 학생이 있는 반"을 기억하지도, 책임지지도 않는다.

## 안전 경계

AI 기능이 늘어도 안전 설계는 그대로다. 오히려 여기가 제일 위험한 지점이므로 경계를 먼저 못박는다.

| 경계 | 규칙 |
|---|---|
| 학급 특성 | `lecture_sessions`에만. `students`·`survey_responses`에 절대 붙이지 않는다 (ADR-016) |
| 학급 특성 입력 | 고정 체크박스 목록. 자유 텍스트 입력란을 열지 않는다 — 열면 담당 교사가 특정 학생의 진단명을 적는다 |
| 과거 설문 | 집계값만. 개별 응답을 행 단위로 넘기지 않는다 |
| 작은 표본 | 응답 5건 미만이면 집계를 통째로 제외 (k-익명성 최소 조치, ADR-018) |
| 자유서술 | `lib/moderation` 마스킹 통과분만 LLM에 보낸다. 추천·교안 양쪽 동일 |
| 교안 열람 | 작성 강사 · 발주 기관 · 운영자 셋뿐. 타 강사 0행, anon 0행 (ADR-019) |
| API 키 | LLM 호출은 `app/api/` 라우트에서만. 클라이언트 번들에 키가 가는 경로를 만들지 않는다 |
| 학생 개인화 | 학생 수준 진단·개인 학습경로를 만들지 않는다 (영구 제외) |
| 기관 AI | 회차 기획 입력에 개별 학생 데이터를 넣지 않는다. 쓰는 것은 지역 공급 현황과 **집계된** 미충족 수요뿐 |

**왜 5건인가**: 응답이 2건인 회차에서 "관심 분야 50% 코딩"은 분포가 아니라 특정 학생 한 명의 답이다. 담당 선생님은 누가 응답했는지 대체로 알고 있다. 가명코드로 막아 둔 것을 집계가 우회하게 두지 않는다.

## 실패해도 화면은 뜬다

두 기능 모두 LLM 실패 시 규칙 기반 결과로 **200을 반환한다.**

| | LLM 성공 | LLM 실패 |
|---|---|---|
| 학생 추천 | 순위 + 생성된 이유 한 줄 | 규칙 순위 + 규칙 문구 |
| 교안 | 차시 흐름 + 난이도 분기 | 프로그램 outline 기반 골격 템플릿 |
| 회차 기획 | 제안 문장 + 강사 요건 + 준비물 | 지역 공급 현황·미충족 수요 표만 |

학생은 특강 직후 교실에서 그 화면을 보고 있다. **에러 화면을 띄우면 그 관심은 그대로 사라진다.** 강사 쪽도 같다 — 수업 전날 밤에 도구가 안 되면 다시 열지 않는다.

키 없음 · 한도 초과 · 타임아웃 · 스키마 변경이 전부 같은 폴백으로 떨어진다. `source` 필드에 `llm` / `rule`을 기록해 검수와 로그에 쓴다. 화면에 "AI가 만들었어요" 배지를 달기 위한 값이 아니다.

## 비용

모델은 `claude-opus-5` (입력 $5 / 출력 $25 per MTok).

| | 호출당 | 빈도 |
|---|---|---|
| 학생 추천 | 약 30원 | 설문 1건당 1회 |
| 교안 생성 | 약 100원 | 회차당 1~2회 |
| 회차 기획 | 약 50원 | 회차 생성당 1~2회 |

파일럿 규모(특강 5~10회차, 응답 수백 건)에서 총액이 수만 원을 넘지 않는다. 비용이 문제가 되면 `claude-sonnet-5`로 내리는 선택지가 있으나 품질 확인 전에 먼저 내리지 않는다.

## 만들지 않는 것

- 학생 개인 수준 진단, 개인별 학습경로 (영구 — ADR-003이 무너진다)
- 학생용 활동지 · 학교 제출용 계획서 서식 자동 생성 (MVP 제외)
- 교안 코퍼스의 익명화·재사용·타 강사 공유 (ADR-019)
- AI 기반 강사 자동 심사 (사람이 한다 — ADR-008)
- AI 모더레이션 (금칙어 규칙 필터 + 사람)
- 자체 모델 학습·파인튜닝
