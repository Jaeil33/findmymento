# AI 설계

Find My Mento에서 AI가 어디에 있고, 왜 거기에 있는가. 이 문서 하나로 설명이 끝나야 한다.

관련 결정: ADR-004(학생 추천), ADR-016(학급 특성), ADR-017(수업 설계 도우미), ADR-018(과거 설문 입력), ADR-019(교안 소유), ADR-021(회차 기획 도우미), ADR-024(수업 후 AI 3종), ADR-026(보호자 문의 도우미).

---

## 원칙 한 줄

> **연결이 제품이고, AI는 그 연결을 실행 가능하게 만드는 공급자 도구다.**

학생에게 가는 AI는 QR을 찍을 이유 한 줄까지다. 보호자에게는 문의 글을 정리해 주는 도우미 하나가 간다(기능 7) — 강사가 받는 리드를 답할 수 있게 만드는 도구이고, 학생 데이터를 늘리지 않는다. 그 이상의 AI는 전부 강사·기관 쪽으로 간다. 이유는 두 개다.

1. **돈을 내는 쪽의 노동을 줄여야 구독이 성립한다.** 학생과 보호자에게는 과금하지 않는다.
2. **학생 데이터를 늘리지 않아야 가명코드 설계가 유지된다.** 학생에게 더 똑똑한 AI를 주려면 학생을 더 많이 알아야 하는데, 이 서비스는 학생을 알지 않기로 하고 시작했다 (ADR-003).

## 어떻게 여기까지 왔는가

| | 1차 구상 | 2차 구상 | 현재 |
|---|---|---|---|
| AI의 역할 | 제품 그 자체 | QR을 찍을 이유 | 공급자의 실행 도구 |
| 개인화 단위 | 학생 한 명 | — | **학급 한 반** |
| 수혜자 | 학생 | 학생 | **강사·기관** |
| 첫 수업에서 | 데이터 0 — 작동 안 함 | 작동 | 작동 |

1차에서는 학생의 활동 데이터(미션 성공 여부, 수행 시간, 모델링 결과)를 쌓아 개인별 다음 활동과 난이도를 추천하려 했다. 두 가지가 걸렸다. **첫 수업 첫 학생에게는 데이터가 0이고**, 데이터를 모으려면 미성년자 개인 기록을 축적해야 한다.

2차에서는 AI를 제품의 중심에서 내리고 연결을 제품으로 삼았다. 문제 정의는 맞았지만 AI가 학생 화면 한 곳에만 남았다 — **돈을 내지 않는 쪽에만.**

현재는 개인화를 버리지 않고 **단위를 올렸다.**

| | 학생 한 명 단위 | 학급 한 반 단위 |
|---|---|---|
| 필요한 데이터 | 개인별 활동 이력 축적 | 기관이 이미 아는 회차 조건 |
| 첫 수업에서 | 작동하지 않음 | 즉시 작동 |
| 미성년자 정보 | 개인 기록을 쌓아야 함 | 학생을 식별하지 않음 |
| 수혜자 | 과금하지 않는 학생 | 구독료를 내는 강사·기관 |

한 칸을 옮기자 콜드스타트와 미성년자 데이터 문제가 동시에 사라졌다.

## AI 기능 1 — 학생 추천 (기존)

**언제**: 특강 마지막 3분, 설문 제출 직후
**누구**: 학생 (로그인 없음)
**무엇**: 우리 지역에서 다음에 들을 수 있는 교육 카드 3~5장 + 추천 이유 한 줄

```
규칙 필터 (SQL)           LLM
────────────────          ──────────────
지역 (시군구→인접→2-hop)   후보 안에서 순위
대상 학년                  이유 한 줄 (50자, 존댓말)
관심 분야
강사 승인 상태
   ↓                         ↓
후보 확정 ──────────────→ 순위 + 문구
```

**LLM은 후보를 새로 만들 수 없다.** 존재하지 않는 강사를 추천하는 환각이 구조적으로 불가능하다. 구현은 `src/lib/ai/recommend.ts`.

이 기능은 **더 키우지 않는다.** 학생별 수준 진단, 개인 학습경로, 장기 프로필은 만들지 않는다.

**예외 — 추천할 수업이 0건일 때 진로 카드 3장 (ADR-027).** 같은 구조를 쓴다: 규칙이 검수된 진로 목록(`src/data/careers.ts`)에서 후보를 확정하고, LLM은 3개를 고르고 이유 한 줄만 쓴다. 카드에는 직업 이름·하는 일·관련 학과/자격·이유만 들어가고, 수준 평가·공부 순서는 넣지 않는다. 구현은 `src/lib/ai/career.ts`.

## AI 기능 2 — 수업 설계 도우미 (신규)

**언제**: 회차 배정 후, 수업 전
**누구**: 배정된 강사
**무엇**: 이 반 조건에 맞춘 교안 초안 — 차시 흐름 + 단계별 난이도 분기

### 입력

```
① 회차 조건        기관이 회차를 만들 때 입력 (ADR-016)
   시수 · 장소 · 예상 인원 · 학급 특성 · 보유 장비

② 강사 프로그램     이미 등록돼 있는 outline
   "드론 조종 기초 3차시" 의 차시 구성

③ 지난 회차 설문     같은 기관 + 같은 분야, 응답 5건 이상일 때만 (ADR-018)
   만족도 · 후속 의향 · 관심 분야 분포 · 자유서술에서 반복된 표현
```

③이 이 제품의 전부다. ①②는 잘 만든 폼이고, ③은 **우리만 가진 것**이다.

### 출력

```
[전개 2단계] 드론 자율비행 코딩 (15분)
  기본        블록 3개로 사각형 경로 만들기
  빨리 끝남    장애물 회피 조건 추가
  어려워함     경로를 2개 블록으로 줄이고 교사가 1개 시범
  통합학급     짝 활동으로 전환, 조종 담당 / 코딩 담당 분리
```

마지막 줄은 그 회차에 해당 조건이 있을 때만 생성된다. 강사가 가장 자주 포기하는 부분이 **진도 편차 대응**이고, 그게 여기 있다.

산출물 범위는 **차시 흐름 + 난이도 조절안까지**다. 학생 활동지와 학교 제출용 계획서 서식은 만들지 않는다.

## AI 기능 3 — 회차 기획 도우미 (기관·학교용)

**언제**: 회차를 만들기 전
**누구**: 기관·학교 담당자
**무엇**: 어떤 특강을 열어야 하는지의 초안

### 입력

```
① 담당자가 입력     대상 학년 · 인원 · 시수 · 목적 · 예산대
② 시스템이 이미 앎   우리 지역 강사·프로그램 공급 현황
③ 시스템이 이미 앎   관내 미충족 수요 집계 (공급 없음 / 장소 없음)
```

### 출력

```
제안  중2 자유학기 주제선택 · 25명 · 2시간
      → 드론 조종 입문 2차시가 맞습니다. 관내 공급 3곳.
      → 강사에게 요구할 것: 기체 10대 이상 지참, 실내 비행 가능 기체
      → 사전 준비물: 강당 또는 체육관, 전원 2구
참고  관내 VR 관심 14명 · 공급 0 — 지금은 열 수 없지만 예산 기안의 근거가 됩니다
```

후보 분야와 강사 요건은 **규칙**이 확정한다. LLM은 문장만 만든다. 존재하지 않는 공급을 제안하는 일이 구조적으로 불가능하다.

**왜 이걸 만드나**: 담당 선생님의 현재 대안은 꿈길도 크레존도 아니다. **작년 파일을 열어 작년 업체에 전화하는 것**이다. 비용 0 · 학습 0 · 리스크 0인 이 선택을 이기려면 더 좋은 강사를 보여주는 것으로는 부족하고 **지금 하는 일을 줄여야** 한다. 기관 과금의 근거가 여기서 나온다 (ADR-021).

## 수업 후 AI — 기능 4·5·6 (ADR-024)

기능 1~3은 수업 **전**과 **직후**에 있다. 수업이 끝난 **뒤** 기관 담당자와 강사가 손으로 하는 일 — 결과보고서, 후속 과정 판단과 섭외 문안, 수업 회고와 학교 제출 요약 — 에는 AI가 없었다. 교과 교사용 AI(생기부 초안·평가 문항·학생 개인 맞춤)는 이미 포화이고 규제도 거기에 몰려 있지만, **외부 직업인 강사가 진행한 1회성 특강의 회차 후 업무**를 돕는 AI는 비어 있다 (`docs/AI_RESEARCH.md`).

세 기능은 같은 설계를 공유한다. 가드는 `src/lib/ai/guard.ts` 한 곳에 두고 세 모듈이 같이 쓴다.

| 공통 규칙 | 내용 |
|---|---|
| 저장 | **아무것도 저장하지 않는다.** 초안을 화면에 보여주고 복사하게 할 뿐이다. 새 테이블·새 RLS 정책이 없다 |
| 분담 | 숫자·후보·사실은 규칙이 확정하고 LLM은 문장만 쓴다. LLM이 실패하면 규칙 초안으로 200 |
| 표본 | 응답 5건 미만 회차는 만족도·후속 의향·관심 분야·학생 의견을 싣지 않고 LLM도 부르지 않는다 (ADR-018 임계치) |
| 숫자 가드 | LLM 문장에 규칙이 주지 않은 숫자가 있으면 그 문장을 버린다 |
| 이름 가드 | LLM 문장에 강사명·기관명·업체명이 있으면 버린다. 연락처·링크는 `maskForStorage`로 거른다 |
| 단위 | 회차. 학생 개인을 지목·평가하는 문장을 만들지 않는다 |
| 권한 | 기능 4·5는 `org_member` + 자기 기관 회차, 기능 6은 `instructor` + 그 회차의 배정 강사. 역할이 틀리면 403, 회차가 없거나 남의 회차면 404 (둘을 구분하지 않는다) |

### 기능 4 — 결과보고서 초안 (기관·학교용)

**언제**: 회차 응답이 모인 뒤
**누구**: 발주 기관·학교 구성원
**무엇**: 상급기관·학교에 내는 회차 결과보고서 초안. 버튼 `결과보고서 초안 만들기`, API `POST /api/result-report`

```
① 회차 조건      일시 · 장소 · 대상 학년대 · 예상 인원 · 시수 · 분야 · 배정 강사
② 회차 집계      응답 수 · 응답률 · 만족도 평균 · 후속 의향 3점 이상 수·비율 · 관심 분야 상위
③ 학생 자유서술   maskForStorage를 다시 통과한 인용 최대 5개
```

LLM 페이로드에는 강사명·기관명·업체명·`student_id`·가명코드·개별 응답 행이 들어가지 않는다. 배정 강사명은 규칙이 채우는 운영 개요에만 쓰인다.

| 출력 섹션 | 규칙과 LLM의 분담 |
|---|---|
| 제목 (`{회차 제목} 운영 결과보고(초안)`) | 규칙 |
| 운영 개요 — 일시·장소·대상·예상 인원·시수·분야·배정 강사 | 규칙 |
| 지표 — 응답 수·응답률·만족도 평균·후속 의향 3점 이상 수와 비율·관심 분야 상위 | 규칙 |
| 성과 요약 · 학생 의견 요약 · 개선점 · 후속 계획 | LLM (실패·가드 탈락 시 규칙 문장) |
| 창체 진로활동 기록 참고 문구 | LLM (실패·가드 탈락 시 규칙 문장) |
| 고지문 | 규칙 |

**창체 기록 참고 문구**는 회차 단위 활동 서술 **한 문장**이다. 2026 학교생활기록부 기재요령에 따라 강사명·기관명·상호명과 숫자를 넣지 않고, 화면에 "AI가 만든 문장을 그대로 입력하지 말 것 / 학교가 주최·주관한 활동에만 기재 가능"을 고지한다. **학생 개인별 특기사항 문장은 만들지 않는다** (영구).

응답 5건 미만이면 지표의 만족도·후속 의향·관심 분야와 학생 의견 요약이 비고, 개선점에 "마무리 3분 전 QR 안내" 규칙 문장이 들어가며, LLM을 부르지 않는다.

### 기능 5 — 후속 과정 제안 + 섭외 요청 문안 (기관·학교용)

**언제**: 결과를 확인한 뒤, 섭외 요청을 보내기 전
**누구**: 발주 기관·학교 구성원
**무엇**: 이 회차 응답으로 볼 때 어떤 후속 과정을 누구에게 요청할 수 있는지의 초안. 버튼 `후속 과정 제안받기`, API `POST /api/followup-plan`

```
① 후속 수요 집계   후속 의향 3점 이상 응답의 관심 분야 1위 · 참여 가능 시간 1위
② 강사 공급       기관 지역 기준 같은 시군구 → 인접 → 2-hop 의 그 분야 승인 강사
③ 원 회차 조건    제목 · 분야 · 학년대 · 시수
```

| 출력 | 규칙과 LLM의 분담 |
|---|---|
| 분야 · 관심 응답 수 · 권장 시간대 · 공급 여부 | 규칙 |
| 강사 후보 (최대 3, 공개 프로필 링크만) | 규칙 — LLM이 늘리거나 바꿀 수 없다 |
| 과정 제목 · 차시 구성 (기본 4차시) | LLM (실패·가드 탈락 시 규칙 값) |
| 섭외 요청 문안 (400자 이내, 기존 섭외 화면의 요청 메모에 붙여 넣는다) | LLM (실패·가드 탈락 시 규칙 문안) |
| 고지문 | 규칙 |

- **후보 정렬은 거리 → 이름뿐이다.** 소속 업체·구독·결제 여부를 반영하지 않는다 (ADR-009). 후보에 연락처 필드가 없다.
- **모집·정원·수강료·신청 폼을 다루지 않는다** (ADR-023). LLM 문장에 그런 단어가 들어가면 버린다.
- **섭외 요청을 자동 발송하지 않는다.** 기관이 문안을 복사해 `/org/recruitment`에서 직접 보낸다.
- 관내·인접(2-hop)에 그 분야 승인 강사가 없으면 후보 없이 **미충족 수요**로 안내하고 LLM을 부르지 않는다. 신규 강사 발굴의 근거가 된다.
- 응답 5건 미만이거나 후속 의향 3점 이상 응답이 0건이면 제안하지 않고 이유만 보여준다.

### 기능 6 — 수업 회고 + 학교 제출용 결과 요약 (강사용)

**언제**: 회차 응답이 모인 뒤 (D+1)
**누구**: 그 회차의 배정 강사
**무엇**: 잘 된 점 · 다음에 바꿀 점 · 학교·기관에 낼 결과 요약. 버튼 `수업 회고 만들기`, API `POST /api/session-debrief`

```
① 배정 회차 집계   응답률 · 만족도 평균 · 만족도 4·5점 / 1·2점 비율 · 후속 의향 3점 이상 비율 · 관심 분야 1위
② 회차 조건        분야 · 학년대 · 시수 · 장소 · 학급 특성
③ 그 회차 교안     있으면 단계의 구분·제목만 (기능 2 산출물)
```

학생 인용문·`student_id`·가명코드·강사명·기관명은 LLM에 보내지 않는다.

| 출력 | 규칙과 LLM의 분담 |
|---|---|
| 잘 된 점 (최대 3) · 다음에 바꿀 점 (최대 3) | 규칙 트리거가 항목을 정하고 LLM이 문장을 다듬는다 (실패 시 규칙 문장) |
| 학교 제출용 결과 요약 (400자 이내) | LLM (실패 시 규칙 문장) |
| 고지문 | 규칙 |

규칙 트리거 (표본 충분일 때):

| 조건 | 제안 |
|---|---|
| 만족도 4·5점 비율 70% 이상 | 잘 된 점 — 만족 응답 비율 |
| 후속 의향 3점 이상 비율 40% 이상 | 잘 된 점 — 후속 과정 제안의 근거가 된다 |
| 후속 의향 3점 이상 비율 40% 미만 (USER_FLOW H2 임계치) | 바꿀 점 — 마무리에 다음 단계 안내 강화 |
| 만족도 1·2점 비율 20% 이상 | 바꿀 점 — 어려워하는 학생용 난이도 분기 점검 |
| 관심 분야 1위가 회차 분야와 다름 | 바꿀 점 — 마무리에 그 분야와 이어지는 직업 소개 |
| 응답률 50% 미만 | 바꿀 점 — QR 안내를 수업 종료 3분 전에 |

회고는 **강사 자신을 위한 집계**다. 점수·등급·순위 같은 강사 평가 표현을 쓰지 않고, 학생 개인을 평가하지 않는다. 응답 5건 미만이면 통계 없이 "다음 회차에는 QR 안내를 먼저" 한 줄만 나오고 LLM을 부르지 않는다.

## AI 기능 7 — 보호자 문의 도우미 (ADR-026)

**언제**: 보호자가 문의 폼(`/inquiry`)을 쓰기 직전
**누구**: 보호자 (로그인 없음)
**무엇**: 아이 상황 설명 → 정리된 조건 + 조건에 맞는 프로그램 + 강사에게 보낼 문의 글 초안. 버튼 `문의 내용 정리하기`, API `POST /api/inquiry-assist`

```
보호자 설명 (자유 텍스트)
   ↓ 가림: 연락처·링크·학교명·이름(lib/moderation) → 줄인 학교명 → 나이·생년 → 학년 숫자
규칙                                  LLM
─────────────────────────             ──────────────
학년대·관심 분야·희망 시간대 (키워드)    문의 글 한 편 (300자, 보호자 목소리)
공개 디렉토리 검색 (searchDirectory)
  승인 강사 · 같은 시군구→인접→2-hop
  최대 3개 · 업체·구독 무관 정렬
```

| 출력 | 규칙과 LLM의 분담 |
|---|---|
| 학년대 · 관심 분야 · 희망 시간대 | 규칙 (글에 단서가 없으면 폼 선택값, 그것도 없으면 비움) |
| 조건에 맞는 프로그램 (최대 3, 공개 상세 링크만) · 지역 단계 문장 | 규칙 — LLM이 늘리거나 바꿀 수 없다 |
| 문의 글 초안 | LLM (실패·가드 탈락 시 규칙 글) |
| 고지문 (초안 · 가림 여부 · 저장 안 됨) | 규칙 |

- **왜 보호자에게 AI를 주나**: 보호자 문의는 강사에게 전달되는 리드다(ADR-014). "연락 주세요" 한 줄짜리 리드는 강사가 답할 수 없고, 아이 실명·학교가 적힌 리드는 받으면 안 된다(E-22). 도우미는 둘을 같은 자리에서 막는다 — 쓰는 사람은 보호자이고, **답할 수 있는 리드를 받는 쪽은 강사**다.
- **LLM에 가는 것**: 가린 설명과 규칙 조건뿐이다. 원문·강사명·프로그램 목록은 보내지 않는다.
- **가드**: 문의 글에 숫자(분야명 제외)·가림 표시·학교명(줄인 이름 포함)·연락처·링크가 있으면 버린다. LLM 응답에서 읽는 값은 `message` 하나다.
- **저장하지 않는다.** 보호자가 `이 내용으로 폼 채우기`를 눌러야 폼에 들어가고, 접수는 기존 `/api/inquiry` 하나뿐이다. 비로그인이므로 IP당 1분 10회로 제한한다.
- 학생 개인의 수준 진단·학습경로가 아니다. 공개 디렉토리의 필터 세 개를 보호자 대신 채우고 문의 글을 다듬는 일까지다.

## "그냥 ChatGPT에 물어보면 되지 않나"

심사에서 반드시 나오는 질문이고, 답은 하나뿐이다.

> **범용 모델은 이 학교 학생들이 지난번에 조종보다 조립에 반응했다는 사실을 모른다. 우리는 그 데이터를 갖고 있다 — 학생이 특강 직후 찍은 QR에서 나왔다.**

```
특강 → QR → 설문 → 추천 카드 (학생)
                 ↓
              설문 집계
                 ↓
        다음 회차 교안 초안 (강사)
                 ↓
              다음 특강 → QR → 설문 → …
```

루프가 여기서 닫힌다. **회차가 쌓일수록 교안이 좋아지는 구조**이고, 이것이 우리 데이터가 제품을 개선하는 첫 경로다. 프롬프트는 복제할 수 있지만 그 교실에서 나온 응답은 복제할 수 없다.

부수적인 답 둘:

- **입력이 이미 시스템에 있다.** 강사는 회차 조건을 다시 적지 않는다. 프롬프트를 쓰는 것 자체가 장벽인 40~60대 현장 강사에게는 이쪽이 더 실질적이다.
- **안전·접근성 규칙이 제품에 박혀 있다.** 범용 챗봇은 "휠체어 학생이 있는 반"을 기억하지도, 책임지지도 않는다.

수업 후 AI(기능 4~6)에도 같은 답이 한 번 더 적용된다. 범용 챗봇에 결과보고서를 부탁하려면 담당자가 먼저 설문을 엑셀로 옮기고, 평균을 내고, 자유서술을 골라 붙여 넣어야 한다. **우리는 그 회차의 집계를 이미 갖고 있으므로 옮기고 요약하는 일 자체가 사라진다.** 붙여 넣는 과정에서 학생 문장이 마스킹 없이 외부 서비스로 나가는 일도 같이 사라진다.

## 안전 경계

AI 기능이 늘어도 안전 설계는 그대로다. 오히려 여기가 제일 위험한 지점이므로 경계를 먼저 못박는다.

| 경계 | 규칙 |
|---|---|
| 학급 특성 | `lecture_sessions`에만. `students`·`survey_responses`에 절대 붙이지 않는다 (ADR-016) |
| 학급 특성 입력 | 고정 체크박스 목록. 자유 텍스트 입력란을 열지 않는다 — 열면 담당 교사가 특정 학생의 진단명을 적는다 |
| 과거 설문 | 집계값만. 개별 응답을 행 단위로 넘기지 않는다 |
| 작은 표본 | 응답 5건 미만이면 집계를 통째로 제외 (k-익명성 최소 조치, ADR-018) |
| 자유서술 | `lib/moderation` 마스킹 통과분만 LLM에 보낸다. 추천·교안 양쪽 동일 |
| 교안 열람 | 작성 강사 · 발주 기관 · 운영자 셋뿐. 타 강사 0행, anon 0행 (ADR-019) |
| API 키 | LLM 호출은 `app/api/` 라우트에서만. 클라이언트 번들에 키가 가는 경로를 만들지 않는다 |
| 학생 개인화 | 학생 수준 진단·개인 학습경로를 만들지 않는다 (영구 제외) |
| 기관 AI | 회차 기획 입력에 개별 학생 데이터를 넣지 않는다. 쓰는 것은 지역 공급 현황과 **집계된** 미충족 수요뿐 |
| 숫자 가드 | 수업 후 AI의 LLM 문장에 규칙이 주지 않은 숫자가 있으면 그 문장을 버리고 규칙 문장을 쓴다 (ADR-024) |
| 이름 가드 | 수업 후 AI의 LLM 문장에 강사명·기관명·업체명이 있으면 버린다. 연락처·링크는 `maskForStorage`로 거른다 |
| 저장하지 않음 | 결과보고서·후속 과정 제안·수업 회고는 어떤 테이블에도 쓰지 않는다. 화면 표시와 복사뿐이다 |
| 수업 후 AI의 작은 표본 | 회차 응답 5건 미만이면 만족도·후속 의향·관심 분야·학생 의견을 싣지 않고 LLM을 부르지 않는다 |
| 창체 기록 참고 문구 | 회차 단위 활동 서술 한 문장. 강사명·기관명·상호명·숫자 없음. "그대로 입력 금지 / 학교 주최·주관 활동만 기재 가능"을 고지한다. 학생 개인별 특기사항 문장은 만들지 않는다 (영구) |
| 후속 과정 제안 | 모집·정원·수강료·신청 폼을 다루지 않는다 (ADR-023). 강사 후보는 규칙이 고르고 정렬은 거리·이름뿐 (ADR-009). 섭외 요청을 자동 발송하지 않는다 |
| 보호자 문의 도우미 입력 | 가린 설명과 규칙 조건만 LLM에 보낸다. 아이 이름·학교(줄인 이름 포함)·연락처·나이·학년 숫자를 먼저 지운다 (ADR-026) |
| 보호자 문의 도우미 출력 | 문의 글 한 편만 LLM이 쓴다. 숫자·가림 표시·학교명·연락처가 있으면 버린다. 프로그램은 공개 디렉토리 규칙으로만 고르고, 아무것도 저장하지 않는다 |

**왜 5건인가**: 응답이 2건인 회차에서 "관심 분야 50% 코딩"은 분포가 아니라 특정 학생 한 명의 답이다. 담당 선생님은 누가 응답했는지 대체로 알고 있다. 가명코드로 막아 둔 것을 집계가 우회하게 두지 않는다.

## 실패해도 화면은 뜬다

모든 AI 기능이 LLM 실패 시 규칙 기반 결과로 **200을 반환한다.**

| | LLM 성공 | LLM 실패 |
|---|---|---|
| 학생 추천 | 순위 + 생성된 이유 한 줄 | 규칙 순위 + 규칙 문구 |
| 교안 | 차시 흐름 + 난이도 분기 | 프로그램 outline 기반 골격 템플릿 |
| 회차 기획 | 제안 문장 + 강사 요건 + 준비물 | 지역 공급 현황·미충족 수요 표만 |
| 결과보고서 | 규칙 개요·지표 + 생성된 성과·의견·개선점·후속 계획·창체 참고 문구 | 규칙 개요·지표 + 규칙 문장 |
| 후속 과정 제안 | 규칙 수요·후보 + 생성된 과정 제목·차시·섭외 문안 | 규칙 수요·후보 + 규칙 과정안·문안 (공급 0이면 미충족 수요 안내) |
| 수업 회고 | 규칙 트리거 + 생성된 문장·학교 제출 요약 | 규칙 트리거 문장 + 규칙 요약 |
| 보호자 문의 도우미 | 규칙 조건·프로그램 + 생성된 문의 글 | 규칙 조건·프로그램 + 규칙 문의 글 |

학생은 특강 직후 교실에서 그 화면을 보고 있다. **에러 화면을 띄우면 그 관심은 그대로 사라진다.** 강사 쪽도 같다 — 수업 전날 밤에 도구가 안 되면 다시 열지 않는다.

키 없음 · 한도 초과 · 타임아웃 · 스키마 변경이 전부 같은 폴백으로 떨어진다. 수업 후 AI에서는 숫자·이름 가드에 걸린 문장도 같은 폴백으로 떨어진다 — 필드 단위로 규칙 문장이 남는다. `source` 필드에 `llm` / `rule`을 기록해 검수와 로그에 쓴다. 화면에 "AI가 만들었어요" 배지를 달기 위한 값이 아니다.

## 데모 배포의 시연용 AI 응답 (ADR-025)

데모 배포에는 LLM 키가 없다. 그 상태에서 AI 기능 7개는 규칙 문장 대신 **시연용 AI 응답**을 쓴다.

| 모드 | 조건 | 문장을 만드는 것 | source 표시 |
|---|---|---|---|
| `llm` | `ANTHROPIC_API_KEY` 있음 | 실제 LLM | `AI가 문장을 정리했습니다` |
| `demo` | 데모 데이터 모드 + 키 없음 + `DEMO_AI≠off` | `lib/ai/demo-writer.ts` | `시연용 AI 문장입니다` |
| `rule` | 그 밖 전부 (실 DB + 키 없음 포함) | 규칙 | `응답 집계로 만들었습니다` 등 |

- 시연 응답은 **LLM에 보내는 페이로드와 같은 값만 읽는다.** 학생 원문·이름·가명코드를 읽지 않는다.
- 결과는 LLM 응답과 **같은 병합·가드**를 통과한다. 숫자·후보·항목·고지문은 바뀌지 않는다.
- 표본 5건 미만·공급 0·제안 불가 회차는 시연 모드에서도 규칙 결과다.
- 현재 모드는 `/api/health`의 `ai_mode`로 확인한다.
- 시연 자리에서는 "LLM 연결 전 시연 응답"이라고 소개한다. 키를 넣으면 같은 자리에 실제 생성 문장이 들어간다.

| 보호자 문의 도우미 | 약 20원 (추정) | 문의 1건당 1~2회 |

수업 후 AI 3종의 단가는 입력·출력 길이를 회차 기획과 비슷하게 가정한 추정이다. 응답 5건 미만 회차와 공급 0인 후속 제안은 LLM을 부르지 않으므로 비용이 0이다.

파일럿 규모(특강 5~10회차, 응답 수백 건)에서 총액이 수만 원을 넘지 않는다. 비용이 문제가 되면 `claude-sonnet-5`로 내리는 선택지가 있으나 품질 확인 전에 먼저 내리지 않는다.

## 만들지 않는 것

- 학생 개인 수준 진단, 개인별 학습경로 (영구 — ADR-003이 무너진다)
- 학생용 활동지 · 학교 제출용 계획서 서식 자동 생성 (MVP 제외)
- 교안 코퍼스의 익명화·재사용·타 강사 공유 (ADR-019)
- AI 기반 강사 자동 심사 (사람이 한다 — ADR-008)
- AI 모더레이션 (금칙어 규칙 필터 + 사람)
- 자체 모델 학습·파인튜닝
- 학생 개인별 학교생활기록부 특기사항 문장 (영구 — 창체 참고 문구는 회차 단위 한 문장까지, ADR-024)
- NEIS 입력·공문 자동 제출 (초안 표시와 복사까지)
- 섭외 요청 자동 발송 (기관이 섭외 화면에서 직접 보낸다 — ADR-024)
- 강사 평점·순위 (수업 회고는 강사 자신을 위한 집계이고 강사를 평가하지 않는다 — ADR-009)
