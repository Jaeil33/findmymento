# PRD: Find My Mento

지역 기반 교육 멘토·강사 매칭 플랫폼. 초·중·고 학생 대상.

## 목표

1회성 진로체험·직업인 특강에서 관심이 생긴 학생을, 기관의 안전한 관리 체계 안에서 지역 강사의 후속 교육으로 연결한다.

핵심 문제는 "강사를 못 찾는다"가 아니라 **관심이 가장 뜨거운 순간(특강 직후)에 다음 단계가 없어서 전환이 끊긴다**는 것이다. 따라서 이 제품은 검색 서비스가 아니라 **전환율 제품**이다.

## 사용자 (우선순위 순)

| 순위 | 사용자 | 역할 | 핵심 니즈 |
|---|---|---|---|
| 1 | 청소년기관·교육업체 담당자 | **결제자** | 인맥 의존 섭외 탈피. 예산 기안·사업 보고에 쓸 수요·만족도 근거 |
| 2 | 강사·직업인·소규모 교육업체 | 공급자 (구독) | 다음 일감의 출처. 본인 수업을 좋아한 학생 집단의 존재 확인 |
| 3 | 학생 (초·중·고) | 실사용자 (무과금) | "더 배우고 싶다"를 말할 창구. 입시가 아닌 흥미 탐색 |
| 4 | 보호자 | 동의권자 | 안전·신뢰. 자녀의 관심 파악 |
| - | 학교 진로전담교사 | **Phase 2** | 학기·예산 주기 제약으로 MVP 제외 |
| - | 지자체·교육지원청 | **Phase 2** | 지역 진로교육 수요 데이터 |

## 확정 결정

1. **파일럿 대상은 청소년기관·교육업체.** 학교는 Phase 2. 행정망 연동·공문·학기 주기 제약을 MVP에서 전부 배제한다.
2. **후속 교육 비용은 기관 사업비.** 학생·보호자는 무과금. 따라서 결제·정산·환불·중개 수수료는 MVP에 없다.
3. **학생 식별은 기관 발급 가명코드.** 플랫폼은 학생 실명·연락처·학교를 일절 저장하지 않는다. 코드↔실명 매핑표는 기관만 보유하며, 플랫폼은 기관의 개인정보 처리 수탁자다. 코드가 없는 학생도 익명으로 설문에 응답할 수 있다(이력 누적만 포기).
4. **후속 교육의 형태는 두 가지.** (a) 기관 공간에서 진행하는 단기과정 4~8회, (b) 학생↔강사 공개 온라인 Q&A.
5. **지역 단위는 시·군·구 + 인접 지역 자동 확장.** 외부 지도 API 없이 행정구역 코드 + 인접 관계 JSON으로 처리한다. **파일럿 지역은 경기도 광명시.** 광명시 인접은 서울 구로구·금천구, 경기 시흥시·부천시·안양시 5곳이고 이 중 2곳이 서울이다. 따라서 "같은 시도(경기도)" 확장은 광명 학생에게 의미가 없다 — 확장 단계에서 시도를 쓰지 않고 **인접의 인접(2-hop)**으로 넓힌다.
6. **관심 분야는 신산업 5개.** 드론, 3D 모델링·프린팅, VR·AR, AI·코딩, 뷰티. 단 **파일럿 시점의 실제 강사 공급은 3D 모델링과 드론 2개뿐이다.** 나머지 3개를 고른 학생에게는 추천이 나가지 않는다. 이 공백을 버리지 않고 **미충족 수요로 집계한다** — "광명시 중학생 VR 관심 14명, 공급 0"이라는 숫자가 곧 신규 강사·업체 영업 자료이자 기관의 예산 기안 근거다.
7. **첫 강사 공급 파트너는 3DNFLY** (3D 모델링·드론 교육 기업. 기획자가 인턴으로 재직 중이라 강사·교육 정보 접근이 가능하다). 단 추천 순위에 소속 업체·구독 여부를 반영하지 않는다 (ADR-009).

## 안전 설계 원칙 (CRITICAL — 모든 기능이 이 제약 아래 놓인다)

1. 학생은 강사의 연락처·SNS·주소를 어떤 경로로도 볼 수 없다.
2. **1:1 비공개 메시지 기능을 만들지 않는다.** 학생↔강사 소통은 공개 스레드뿐이다.
3. 연결의 주체는 항상 기관이다. 학생의 "관심 표현"은 기관 대시보드로 모이고, 기관이 검토·보호자 동의 확인 후 강사를 섭외한다.
4. Q&A는 비동기 전용. 실시간 채팅·푸시 알림 없음.
5. 게시물에서 연락처·외부 링크를 자동 차단한다. 안전 목적이자 플랫폼 외부 직거래 이탈 방지 목적.
6. 미승인 강사는 학생·기관 화면에 노출되지 않는다. 성범죄경력 조회 증빙·자격 증빙을 운영자가 수동 심사한다.

## 핵심 기능 (MVP)

**파일럿 구현 범위는 1 · 2 · 4 · 5 · 7 · 8이다.** 기능 3의 학생용 검색·필터 화면은 만들지 않는다 — 강사가 한 자릿수인 단계에서 쓸 사람이 없다. 단 기능 3의 **지역 확장 규칙은 기능 2(추천) 안에 내장한다.** 기능 6은 운영자 수동 등록으로 대체한다 (ADR-008).

1. **특강 회차 + 피드백 수집** — 기관이 회차를 생성하면 QR/6자리 코드 발급. 학생은 가입 없이 3분 설문(만족도, 관심 분야, 더 배우고 싶은 것, 학년, 관심 직업).
2. **AI 추천** — 설문 제출 직후 학생에게 "다음에 들으면 좋은 교육 / 지역 강사" 3~5장 + 추천 이유 한 줄. 같은 가명코드의 **누적 이력**과 학생이 직접 쓴 문장을 함께 사용한다.
3. **강사·프로그램 디렉토리** — 지역/분야/대상 학년/형태 필터. 결과가 없으면 `같은 시군구 → 인접 시군구(1-hop) → 인접의 인접(2-hop) → Q&A로 유도` 순으로 확장한다. 빈 화면을 보여주지 않는다.
4. **공개 온라인 Q&A** — 학생은 가명(`중2 학생 A`)으로 질문, 강사가 답변, 전원 공개. 기관 담당자가 모더레이터(숨김·신고 처리). 질문 텍스트는 추가 수요 데이터로 쓴다.
5. **기관 대시보드** — 회차별 만족도·수요 클러스터, 수요 기반 강사 추천, 섭외 요청 발송·상태 추적, 보호자 동의 여부 기록.
6. **강사 프로필·프로그램 등록 + 수동 심사** — MVP에서는 운영자가 대신 등록해주는 수준으로 충분하다.
7. **미충족 수요 집계** — 관심은 있으나 지역 내 공급이 없는 분야를 기관 대시보드와 운영자 화면에 따로 모은다. 공급이 2개 분야뿐인 파일럿에서 가장 먼저, 가장 많이 쌓일 데이터다. 강사 영업과 기관 제안에 그대로 쓴다.
8. **공개 랜딩 1장 + 초대 기반 로그인** — 서비스 소개·대상별 가치·문의 버튼과 로그인 진입구만. 마케팅 토피터는 만들지 않는다 (첫 기관은 3DNFLY 거래처에서 직접 섭외로 온다). 계정은 셀프 가입 없이 초대로만 생성한다 (ADR-011).

## MVP 제외 사항

- 결제·정산·환불·중개 수수료
- 1:1 채팅, 실시간 알림, 푸시 (영구 제외 — 안전 설계상)
- 모바일 앱 (모바일 웹으로 대응)
- 수강·출결 관리(LMS), 학교 행정망·NEIS 연동
- 자동 성범죄경력 조회 API, 지도 기반 탐색, 지오코딩
- 학생 본인 로그인·장기 프로필, 보호자 전용 포털
- 강사 셀프 온보딩 퍼널 (운영자 수동 등록으로 대체)
- 학생용 강사 검색·필터 탐색 화면 (추천 결과 화면으로 대체)
- 리포트 PDF 내보내기 (화면 조회만)
- 리뷰·평점 시스템

## 사용자 흐름

```
[학생]   특강 종료 → QR → 가명코드 입력(또는 익명) → 설문 3분
                  → AI 추천 카드 즉시 노출
                  → "더 배우고 싶어요"(관심 표현) 또는 Q&A 질문 작성
[기관]   특강 회차 생성 → QR 배포 → 수요·만족도 확인 → 추천 강사 확인
                  → 섭외 요청 발송 → 단기과정 개설 → 학생 모집
                  → (개설된 과정도 다시 피드백 수집 → 루프)
[강사]   운영자 등록·심사 승인 → 프로필/프로그램 등록 → Q&A 답변으로 전문성 노출
                  → 지역 수요 알림 수신 → 섭외 요청 수락 → 일정 제안
[보호자] 기관이 발송한 동의 확인 → 기관이 동의 여부를 대시보드에 기록
```

## 파일럿 실행 경로 (E2E)

첫 파일럿은 아래 한 줄을 끝까지 통과시키는 것이 전부다. **이 경로에 없는 기능은 2차로 미룬다.**

1. 3DNFLY가 광명시 내 학교·청소년기관에서 진로체험 특강을 진행한다 (이미 일어나고 있는 일).
2. 해당 기관이 플랫폼에 특강 회차를 등록하고 QR을 출력해 현장에 붙인다.
3. 학생이 가명코드로 설문에 응답한다.
4. 설문 직후 추천이 뜬다. 공급이 있는 분야(3D 모델링·드론)는 강사 카드가, 없는 분야(VR·AI·뷰티)는 Q&A 유도가 뜬다.
5. 기관 담당자가 대시보드에서 만족도·수요·**미충족 수요**를 확인한다.
6. 기관이 후속 단기과정 섭외 요청을 보낸다.
7. 후속 과정이 개설되면 그 회차도 다시 3번으로 돌아간다 (루프 완성).

**성공 판정: 6번이 한 번이라도 실제로 일어나면 MVP는 가설을 검증한 것이다.**

## 운영 준비물 (코드 밖에서 해야 하는 일)

- 3DNFLY와 1호 입점 합의. 사례·데이터 활용 범위를 포함한다. **1호 업체는 구독료를 받지 않고 레퍼런스 조건으로 간다.**
- 강사 개인별 개인정보 수집·이용 동의. 강사는 성인이므로 본인 동의로 충분하다.
- 강사 자격 증빙 + 성범죄경력 조회 증빙 수집 (업체 경유).
- 파일럿 기관과의 개인정보 처리위탁 계약 1부. **가명코드↔실명 매핑은 기관이 보유한다**는 점을 문서에 명시한다.
- 가명코드 배부 방식 결정 (출력 스티커 / 명찰 / 좌석표 중 하나).
- 설문 문항 확정. 이 파일럿에서 가장 중요한 단일 산출물이다. 문항이 틀리면 수집한 데이터 전부가 무용해진다.

## 차별점

1. 진입점이 검색이 아니라 **수업 직후의 관심 최고점**이다.
2. **기관 경유 안전 설계.** 직거래 차단은 제약이 아니라 학교·기관을 뚫는 열쇠다.
3. 관심 데이터를 **기관의 예산·섭외 근거 리포트**로 환산한다.
4. 공급이 강의 콘텐츠가 아니라 **우리 지역에 실재하는 직업인**이다.
5. 가명코드 누적 이력으로 **경로 추천**이 가능하다 (드론 2회 + 3D 1회 → 공간정보·측량).

대안 비교: 꿈길·크레존은 1회성 체험 매칭까지만 다루고 후속이 없다. 탈잉·클래스101은 성인 대상이고 안전 장치가 없다. 지역 학원은 입시 중심으로 신산업 분야가 없다.

## 수익모델

| 순서 | 모델 | 비고 |
|---|---|---|
| 1 | 강사·교육업체 구독 (월 2~5만) | 지역 수요 알림 + 섭외 리드 + Q&A를 통한 전문성 노출. **노출 우대는 팔지 않는다**(ADR-009). 1호 업체 3DNFLY는 레퍼런스 조건으로 무료 |
| 2 | 기관 SaaS 구독 (기관 단위 연 라이선스) | 단가는 크고 예산 주기는 느리다 |
| 3 | 중개 수수료 (성사액 10~15%) | 결제를 붙이는 Phase 2 |
| 4 | 지자체·교육청 수요 리포트·위탁사업 | 마진이 크고 레퍼런스가 된다 |

MVP 기간에는 전 기능 무료로 풀고 **레퍼런스 기관 1~2곳 + 강사 20~30명**을 확보하는 것이 목표다.

## 성공 지표 (이 4단 퍼널만 본다)

설문 응답률 → 관심 표현율 → **기관의 섭외 요청 발송 수** → 후속 과정 개설 수

보조 지표: Q&A 질문 수, 강사 답변률, 재방문율.

## 리스크

1. **후속 전환율** — 강사 공급은 기존 네트워크로 해결되므로, 유일한 진짜 가설은 "특강 들은 학생이 실제로 후속 교육까지 넘어가는가"다.
2. **법적 제약** — 만 14세 미만 법정대리인 동의(개인정보보호법), 아동·청소년 대상 강사의 성범죄경력 조회 의무, 기관과의 개인정보 처리위탁 계약.
3. **코드 배부 실패** — 현장에서 가명코드 배부가 꼬이면 응답률이 떨어진다. 익명 응답 허용이 완화책.
4. **모더레이션 부담** — Q&A 신고 처리 주체가 기관임을 계약·UI에서 명확히 해야 한다.
5. **업체 편중과 이해관계** — 첫 공급이 3DNFLY 한 곳이다. 플랫폼이 특정 업체의 영업 채널로 보이면 2호 업체가 들어오지 않고, 기관도 수요 데이터를 신뢰하지 않는다. 파일럿에서는 문제되지 않지만 두 번째 업체를 받는 시점에 추천 중립성을 증명할 수 있어야 한다. 그래서 중립성을 나중에 붙이지 않고 처음부터 로직에서 배제한다 (ADR-009).

## 디자인 방향

- 기관 담당자 화면은 **매일 쓰는 업무 도구**로 보여야 한다. 마케팅 랜딩 느낌 금지.
- 학생 화면은 **모바일 웹 우선** (특강 현장에서 휴대폰으로 QR 스캔).
- 상세 규칙은 `docs/UI_GUIDE.md`를 따른다.
