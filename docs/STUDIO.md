# 콘텐츠 스튜디오 — 생성 절차와 제약 조건

실습형 교육 콘텐츠를 **만들고 검증하고 수업에 쓰는** 기능의 명세다. 기획 배경은 `docs/PRD.md`,
권한·데이터 모델은 `docs/ARCHITECTURE.md`, 기술 결정은 `docs/ADR.md`(ADR-028~032),
AI 기능 전체 범위는 `docs/AI.md`를 본다.

## 왜 이 기능인가

강사에게 가장 비싼 것은 수업 시간이 아니라 **수업 준비 시간**이다. 3D펜 특강 한 번을 하려면
학년·인원·시수·장비에 맞는 도안을 직접 그려야 하고, 그 도안이 45분 안에 끝나는지는 수업
당일 교실에서야 알게 된다. 드론은 더하다 — 비행 경로가 체육관에 안 들어가면 그 자리에서 수업이
무너진다.

그래서 이 제품이 만드는 것은 "AI가 써 준 글"이 아니라 **교실에 그대로 들고 갈 수 있는 산출물**이다.
도안은 A4에 1:1로 인쇄되는 SVG이고, 드론 코드는 그 체육관에서 실제로 뜨는 비행 코드다.

## 원칙 — 숫자는 코드가 정하고, 문장은 LLM이 쓴다

기존 AI 기능(ADR-004·017·027)과 **같은 분업**이다.

| 무엇 | 누가 |
|---|---|
| 좌표·치수·선 길이·접합 규격 | 결정론적 생성기 (`lib/studio/**`) |
| 제작 시간·난이도·공간 적합성 판정 | 검증기 (고정 임계값) |
| 비행 경로·고도·장애물 간격 | 시뮬레이터 + 검증기 |
| 주제 해석(= 레시피·아틀라스 선택 · 조각 조합 · **윤곽 비율 제안**), 제목, 실습 과제 문장, 지도안 문장 | LLM (목록 안에서, 좌표는 0~1 비율로만) |
| 만든 모양이 그 단어로 보이는가 (검수 안 된 모양만) | LLM 이미지 검토 — warn 만 남기고 **막지 않는다** (ADR-038) |

**LLM은 mm와 접합 규격을 만들지 않는다.** 모델이 그려 준 SVG는 치수가 맞는 것처럼
보이지만 선 간격이 1mm인 도안을 만들고, 그 도안은 교실에서 녹아 붙은 덩어리가 된다.
치수와 판정을 모델에게 맡기는 순간 이 제품의 유일한 차별점이 사라진다.

LLM이 모양에 대해 돌려줄 수 있는 것은 **검수된 목록에서의 선택**과 **단위 없는 비율**뿐이다 —
조각 조합의 비율·수량(ADR-034)과 윤곽의 0~1 정규화 좌표(ADR-036)까지다. 거기에 mm를 곱하고,
접합 길이를 정하고, 배치하고, 판정하는 것은 전부 코드다. 범위·목록을 벗어난 제안은 통째로 버린다
(ADR-027의 진로 카드와 같은 구조). **드론 비행 명령은 여전히 전부 코드가 만든다.**

### 모양은 어디서 오는가 — 경로 넷, 순서 고정 (ADR-036)

| 순서 | 경로 | 검수 | 런타임 LLM |
|---|---|---|---|
| 1 | 레시피 (`pen3d/recipes.ts`) — **3D 조립이 가능한 유일한 경로** | 사람 | 선택만 |
| 2 | 아틀라스 (`src/data/atlas/**`) — 오프라인에서 생산·검증한 실루엣 | 사람 + 스크립트 | **0회** |
| 3 | 윤곽 제안(DSL) — 아틀라스 미적중. 0~1 정규화 좌표 | 없음 → 이미지 검토 | 1회 |
| 4 | 조각 조합(ADR-034) · 유사 아틀라스 → 그마저 없으면 `failed` | 조각만 | 선택만 |

앞 순서가 적중하면 뒤는 보지 않는다. 같은 단어가 두 번째로 들어오면 아틀라스가 LLM 호출 없이
나간다 — 쓸수록 싸고 좋아지는 방향이다.

### 레시피가 먼저다

레시피는 사람이 검수한 모양이고 조합은 그렇지 않다. 그래서 주제와 같은 모양의 레시피가 있으면
**레시피를 쓴다.** 상자·조명·화분·키링·집·탑·드론 프레임·구 장식이 레시피로 있다.

탑(`lattice-tower`)이 그 예다 — 레시피에 탑이 없던 동안 "에펠탑"은 조합으로 떨어져서 받침판 위에
막대 4개를 겹쳐 붙이는 도안이 나왔다. 조립해도 탑이 서지 않는 물건이었다. 주제가 자주 들어오는데
조합이 엉뚱한 모양을 내놓으면, 조각을 늘리기 전에 **레시피를 추가한다.**

### 조합 — 레시피에 없는 주제 (ADR-034)

"물고기"·"토끼"처럼 레시피에 없는 주제는 **검수된 조각**(`lib/studio/pen3d/pieces.ts`)을 조합해
만든다. LLM이 제안할 수 있는 것은 두 가지뿐이다:

| LLM이 정하는 것 | 코드가 정하는 것 |
|---|---|
| 어느 조각을 쓸지 (목록 안에서) | 조각의 mm 치수 · 좌표 |
| 몸통 대비 **가로 비율**(0.12~1.2)과 **수량**(1~6) | 접합 길이·개수·배치·부품 수 상한 |

| 상수 | 값 | 근거 |
|---|---|---|
| 조각 최소 치수 | 14mm | 가장 빡빡한 학년 기준(선분 8mm)에 여유를 둔 값 |
| 조합 조각 종류 상한 | 5 | 몸통 1 + 붙이는 조각 4 |

비율이 작게 와도 조각은 최소 치수 아래로 내려가지 않는다. 목록·범위를 하나라도 벗어나면 조합을
**통째로 버리고** 레시피 선택으로 떨어진다. 만들어진 조합은 레시피와 같은 형태라 아래 파이프라인이
그대로 돌아간다 — 검증기는 조합인지 레시피인지 알지 못한다.

**주제는 강사가 적은 그대로 쓴다** (ADR-043). 캐릭터·상표 이름을 일반 형태로 치환하던 규칙은
걷어냈다 — 이 플랫폼은 무엇이 저작권 침해인지 판정하지 않는다. 치환도 거절도 경고도 책임 고지도
없다. 스튜디오 산출물을 열람하는 주체가 작성 강사·발주 기관·운영자 셋뿐이고(ADR-031) 학생·보호자·
타 강사·anon 에게 도달하는 경로가 하나도 없어, 공개 배포가 구조적으로 불가능하다.

**체험 세션도 이 저작만은 실제 LLM을 쓴다** (ADR-035). 로그인 없이 들어온 방문자가 적은 문장도
같은 경로로 조각 조합이 된다. 상한(`TOUR_LLM_DAILY_MAX`·방문자별 10분 5회)에 걸리면 시연용
응답으로 떨어지고, 그 사실을 화면에 적는다. 숫자의 결정권은 어느 쪽이든 코드에 있다.

**체험은 경로 1·2·4까지다.** 윤곽 제안(DSL)과 이미지 검토는 체험에서 돌리지 않는다 — 익명
공개 경로의 예산이 그 이유이고(ADR-035), 체험 화면에는 "검수된 목록에서 고릅니다"라고 적는다.

### 폴백 사슬 — 2D 는 빈손으로 끝나지 않는다 (ADR-042)

| 순서 | 경로 | LLM | 검수 |
|---|---|---|---|
| 1 | 코퍼스·아틀라스 적중 (`src/data/atlas/**`) | **0회** | 사람이 그린 아트 |
| 2 | 윤곽·색 영역 제안 (DSL) | 1~2회 | 없음 → 이미지 검토 |
| 3 | 유사 코퍼스 모양 | 선택만 | 사람 |
| 4 | **이름 명패** (`pen3d/fallback.ts`) | 0회 | — |

4번이 바닥이다. 둥근 네모 한 장 + 고리이고, 색은 단어에서 **결정론적으로** 고른다(같은 단어는
항상 같은 명패다 — 색이 매번 바뀌면 강사는 생성 버튼을 다시 누른다).

**`PEN_SHAPE_UNAVAILABLE`은 2D 에서 발생하지 않는다.** 예전에는 여기가 실패 화면이었고 거기에
"더 일반적인 단어로 적어 보세요"가 적혀 있었다 — 제품이 할 일을 강사에게 떠넘기는 문구다.

바닥으로 내려간 사실은 `PEN_SHAPE_FALLBACK`(warn)으로 남아 화면에 적힌다. **차단이 아니라
고지다.** 요청한 모양이 나온 것처럼 보이는 것이 유일하게 해서는 안 되는 일이다.

임계값은 하나도 면제하지 않는다 — 명패도 간격·선분·내각·닫힘·A4·시간 검사와 개선 라운드를
그대로 지난다. 3D 는 이 바닥을 쓰지 않는다: 조립되지 않는 명패를 입체 요청의 답으로 내보낼 수 없다.

### 아틀라스 — 검수된 실루엣 (ADR-036)

`src/data/atlas/<단어>.json` 하나가 모양 하나다(`PenShape`). 정규화 좌표(0~1)로 윤곽 1개·내부선·
구멍을 가지고, `words`에 동의어를 적어 둔다. 조회는 결정론이다 — 공백·조사를 떼고 토큰으로
맞춘다. 임베딩·벡터DB를 쓰지 않는다.

적재는 오프라인 스크립트다.

```
npm run studio:atlas -- --words scripts/studio/words/animals.txt
```

단어마다 윤곽 제안 → **세 학년대 전부로 검증** → 래스터 → 이미지 검토(재시도 2회)를 돌리고,
통과한 것만 JSON으로 쓴다. 떨어진 단어는 이유와 함께 `atlas-report.md`에 남겨 사람이 본다.
**통과하지 못한 모양을 아틀라스에 넣지 않는다** — 아틀라스가 가진 값은 "검수됨" 하나다.

### 윤곽 제안 (DSL) — 아틀라스에 없는 단어 (ADR-036)

| LLM이 정하는 것 | 코드가 정하는 것 |
|---|---|
| 윤곽·내부선·구멍의 **0~1 정규화 좌표** | mm 환산 (`params.size`를 곱한다) |
| 고리가 필요한지, 제목·과제 문장 | 스무딩·등간격 리샘플·짧은 선분 병합·예각 완화 |
| (그 외 없음) | 접합 길이·층 수·배치·부품 수 상한·판정 |

보정 순서는 `lib/studio/pen3d/shape.ts` 한 곳에 있고 바뀌지 않는다: 범위·개수 검사 → 닫힘 보정
→ **자기교차면 폐기** → 스무딩·리샘플 → mm 환산 → 선분·각도 정리 → 기존 검증기. 내부선은
`detail` 단계에 매핑하므로, 간격이 모자라면 **모양이 아니라 디테일이 먼저 깎인다.**

| 상수 | 값 | 근거 |
|---|---|---|
| 윤곽 점 개수 (요청) | 8~64 | 8개 미만은 모양이 되지 않고, 64개 초과는 보정 뒤에 의미가 없다 |
| 점 개수 (받아는 주는 한계) | 200 | 더 촘촘히 그려 온 것은 **등간격으로 솎아서** 쓴다. 넘으면 버린다 |
| 내부선 / 구멍 상한 | 6 / 2 | 간격 임계값을 지키면서 A4에 들어가는 한계 |
| 정규화 좌표 범위 | 0~1 | 치수 환산의 기준 |
| 좌표 관용 폭 | ±0.25 | 이 안이면 0~1 로 **끌어당겨** 쓴다 — 모양은 뒤에서 bbox 로 다시 정규화되므로 치수의 결정권은 그대로 코드에 있다. 넘으면 버린다 |

**호출 예산** (실측): 윤곽 한 번이 12~20초다. 한 번의 상한은 18초이고, **다시 그리면 풀리는
거절**(자기교차 등)이면 이유를 되먹여 **한 번 더** 받는다 — 거절이 없으면 1회, 있으면 최대 2회다.
거기에 이미지 검토 8초가 붙는다. 타임아웃·한도는 다시 걸어도 같으므로 재시도하지 않는다.

**쓸 수 없는 선택지를 모델에게 주지 않는다.** 고를 목록이 비어 있으면(2D 의 기본 상황) 프롬프트는
윤곽 제안 하나만 남고, 조각 조합(ADR-034) 지시문은 **입체 요청에만** 들어간다. 세 가지를 한꺼번에
보내면 모델은 조합으로 답하고, 2D 는 조합(접합이 있는 입체)을 쓸 수 없어 실패한다 — 운영에서
"물고기"·"피카츄" 2D 가 전부 실패 화면이 된 원인이 이것이었다.

### 모드 — 2D 실루엣과 3D (ADR-037)

강사가 고른다(`StudioSpec.form`). 수업 조건이 아니라 강사의 선택이라, 회차에서 생성할 때도
강사가 고른다. 기본값은 `flat`이다.

| 모드 | 부품 | 접합 | 접합 검사 |
|---|---|---|---|
| `flat` (2D) | 실루엣 1종 ×1 (+고리) | 고리 1곳 또는 없음 | **받지 않는다** |
| `solid` (3D·조립) | 레시피 그대로 | 레시피 그대로 | 받는다 |
| `solid` (3D·적층) | 같은 실루엣 1종 ×N + 측면 띠(`optional`) | 층간 N−1곳 | 받는다 |

2D가 접합 검사를 받지 않는 것은 **조립하지 않는 산출물**이기 때문이다. 임계값 면제가 아니다 —
간격·선분·내각·닫힘·자기교차·A4·겹침·시간·부품 수는 전부 그대로 받는다.

| 상수 | 값 | 근거 |
|---|---|---|
| 적층 층 수 (초/중/고) | 3 / 4 / 5 | 두께가 보이는 최소 장수에서 시작한다. 시간이 모자라면 줄인다 |
| 측면 띠 분절 | 3 | 둘레를 한 줄로 그리면 A4 사용 폭(190mm)을 넘는다 |
| 2D 고리 바깥 반지름 | 9mm | 두께 5mm를 빼고 구멍이 남는 최소치 (`name-keyring`과 같은 값) |

3D를 골랐는데 그 단어에 조립안이 없으면 **적층으로 만들고 그 사실을 화면에 적는다.** 같은
실루엣이라 인쇄는 한 번(`×N` 표기)이고 A4 한 장 제약은 그대로다.

### 이미지 2차 검토 (ADR-038)

검수되지 않은 모양(경로 3)에만 돌린다. 렌더한 도안을 자체 래스터라이저로 512×512 PNG으로 만들어
LLM에게 **이미지로** 보여 주고 `{"looks_like":bool,"missing":"..."}`만 받는다.

- 부정 판정 → `PEN_SHAPE_UNRECOGNIZED`(warn) + 무엇이 빠졌다는지 화면에 적는다
- 검토 자체가 실패(키 없음·타임아웃·거절·JSON 깨짐) → **부정으로 적지 않는다.** `PEN_SHAPE_UNREVIEWED`가 남는다
- **검토는 한 번만 한다.** 검토 결과로 다시 그리지는 않는다 (윤곽 제안 자체의 재시도는 ADR-036)
- warn이므로 `ok`를 깨지 않는다. 막지 않고 보여 준다 — 물리 검증의 의미를 흐리지 않기 위해서다
- 서버 PDF·래스터 라이브러리는 쓰지 않는다. 스캔라인 채움 + `node:zlib` PNG 인코딩이고 결정론적이다

## 파이프라인 — 생성 → 검증 → 개선 → 재검증 → 승인

```
강사 입력 (학년대 · 학생 수 · 수업 시간 · 보유 장비 · 주제 · 2D/3D)
  │
  ├─ 규칙: 입력 정규화(캐릭터명 일반화) + 레시피·아틀라스 적중 판정 + 후보 확정
  ├─ LLM: 후보 중 선택 · 조각 조합 · 윤곽 비율 제안 + 제목 + 과제 문장  ← 실패·범위 밖이면 뒤 순서로
  │
  ▼
 생성 (파라메트릭 · 결정론적)
  │
  ▼
 검증 ─── error 0건? ──예──▶ validated ──강사 승인──▶ approved (수업 사용 가능)
  │            │
  │           아니오
  │            ▼
  └───── 개선 (파라미터 조정 · 최대 3회) ──▶ 재검증
                 │
            3회 초과 실패
                 ▼
              failed  (수업 사용 가능으로 **표시하지 않는다**)
```

각 라운드는 `validation.rounds`에 남는다 — 무엇이 걸렸고 어떻게 고쳤는지를 강사가 화면에서
그대로 본다. "AI가 알아서 했다"가 아니라 "간격 2.4mm로 미달 → 1.15배 확대 → 3.1mm 통과"로
보여야 강사가 그 결과를 믿고 교실에 들고 간다.

### 상태 모델

| 상태 | 의미 | 내려받기·인쇄 |
|---|---|---|
| `draft` | 생성 중 또는 검증 전 | **막는다** |
| `failed` | error 1건 이상 | **막는다.** findings를 그대로 보여준다. **2D 에서는 발생하지 않는다** (ADR-042) |
| `validated` | error 0건 (warn은 있을 수 있음) | 허용. 단 "강사 확인 필요" 표시 |
| `approved` | 강사가 확인하고 승인 | 허용. 수업 사용 가능 |

**CRITICAL: `failed`·`draft`를 "사용 가능"으로 표시하지 않는다.** 검증을 통과하지 못한 도안이
교실에 들어가면 그 수업은 실패하고, 강사는 두 번째 기회를 주지 않는다.

## 콘텐츠 1 — 3D펜 도안

### 산출물

A4 1:1 SVG. 부품(part)의 윤곽선을 종이 위에 인쇄하고, 학생이 실리콘 매트를 덮거나 그 선 위에
직접 펜으로 덧그려 부품을 만든 뒤, 접합 지시(joint)에 따라 입체로 조립한다. **2D 모드는 조립하지
않고, 떼어낸 한 장이 그대로 산출물이다** (ADR-037).

- 단위는 **밀리미터**다. `viewBox`가 `0 0 210 297`이고 `width="210mm"`다. 축척이 틀리면 전부 무의미하다.
- **같은 모양의 부품은 한 번만 인쇄하고 `×6`처럼 수량을 표기한다.** 학생은 같은 선 위에 여러 번 덧그려 필요한 개수를 만든다 — 3D펜 수업에서 실제로 하는 방식이고, 그래야 6면체가 A4 한 장에 들어간다. 제작 시간은 수량을 곱해 계산하고, A4 적합성은 고유 부품만으로 본다.
- 선은 `stroke`만 쓰고 `fill`은 없다 — 덧그릴 선이기 때문이다.
- 접는 선(굽힘)과 자르는 선(윤곽)을 다르게 그린다: 윤곽은 실선, 굽힘은 파선.

### 물리 상수 (`lib/studio/constants.ts`가 유일한 출처)

| 상수 | 값 | 근거 |
|---|---|---|
| 압출 선폭 | 1.6mm | PLA 1.75mm · 노즐 0.7mm에서 실제로 깔리는 비드 폭 |
| 최소 선 간격 (초/중/고) | 4.0 / 3.0 / 3.0mm | 선폭 + 손떨림 여유. 이보다 좁으면 두 선이 녹아 붙는다 |
| 최소 선분 길이 (초/중/고) | 8 / 6 / 5mm | 이보다 짧으면 학생이 선으로 인식하지 못하고 점이 된다 |
| 최소 내각 (초/중/고) | 40 / 30 / 25° | 더 날카로우면 꼭짓점에 덩어리가 생긴다 |
| 그리기 속도 (초/중/고) | 6 / 9 / 12 mm/s | 학생 기준이다. 멈춤·수정 포함. 장비 스펙 속도가 아니다 |
| 부품 떼어내기 | 30s/부품 | |
| 접합 1건 | 45s | 펜으로 두 부품을 녹여 붙이는 시간 |
| 최소 접합 길이 | 8mm | 이보다 짧은 용접은 떼어낼 때 떨어진다 |
| 수업 오버헤드 | 20분 | 도입·시범 12 + 정리 8. 장비 배부 포함 |
| 시간 안전 계수 | 0.85 | 남은 시간을 전부 쓰지 않는다 |
| 부품 수 상한 (초/중/고) | 6 / 10 / 14 | 1인 기준 |
| A4 사용 영역 | 190 × 277mm | 210×297 − 여백 10mm |
| 부품 간 배치 간격 | 14mm | 떼어내기 여유 + 번호·이름이 옆 부품과 섞이지 않는 거리 |
| 라벨 글자 크기 (이름/치수) | 3.4 / 2.9mm | 인쇄했을 때 교실에서 읽히는 최소 크기 |
| 라벨 줄 간격 | 4.2mm | 윗줄 글자 꼬리와 아랫줄 윗선이 닿지 않는 간격 |
| 라벨 칸 최소 폭 | 32mm | 부품이 이보다 좁아도 칸은 이만큼 잡는다 |

예상 제작 시간 = `총 선 길이 / 속도 + 부품수 × 30s + 접합수 × 45s`
가용 시간 = `(수업 시간 − 20분) × 0.85`

### 배치 단위는 윤곽이 아니라 "칸"이다

부품마다 번호 배지·이름·수량·치수를 윤곽 **아래**에 적는다. 배치기(`lib/studio/pen3d/layout.ts`)가
예약하는 사각형은 `윤곽 + 그 라벨 블록`이고, 칸 폭은 `max(윤곽 폭, 라벨 칸 최소 폭)`이다.
라벨 글자는 그 폭 안에서만 흐르고 넘치면 줄을 바꾼다.

윤곽만 배치하고 라벨을 그 위에 얹으면 ① 아랫줄 부품의 라벨이 윗줄 부품의 선 위로 올라가고
② 윗줄의 아래쪽 라벨과 아랫줄의 위쪽 라벨이 같은 자리에 찍힌다. 인쇄하면 어느 선을 그어야
하는지 알 수 없는 종이가 된다. 그래서 칸 크기는 `lib/studio/pen3d/label.ts` 의 `partCell`
한 곳에서만 나오고, **배치기와 렌더가 같은 함수를 호출한다.**
`tests/studio-pen3d-layout.test.ts` 가 렌더된 SVG 좌표로 겹침을 직접 검사한다.

### 안전 고정 문구 (3D펜, 생성물에 항상 포함)

- 펜 끝(노즐)은 200도 가까이 올라갑니다. 끝을 만지지 않고, 쓰지 않을 때는 거치대에 세워 둡니다.
- 실리콘 매트나 종이 위에서만 그립니다. 책상에 바로 그리면 자국이 남습니다.
- 환기를 하고, 얼굴을 도안에 가까이 대지 않습니다.
- 부품을 뗄 때는 식은 뒤에 떼고, 떼기 어려우면 선생님에게 말합니다.

LLM 이 이 문구를 지우거나 바꿔 쓰면 규칙 문구로 되돌린다.

### 난이도 산정

1~5. 부품 수 · 접합 수 · 곡선 비율 · 최소 특징 크기 · 입체 굽힘 필요 여부를 가중 합산한다.
권장 범위: 초등 1~2, 중등 2~4, 고등 3~5. 벗어나면 `PEN_DIFFICULTY_MISMATCH`(warn)다 —
강사가 일부러 어려운 걸 고를 수 있어야 하므로 막지 않는다.

레시피에 사람이 매겨 둔 `nominal_difficulty` 와 이 **측정 난이도**는 다른 값이다. 전자는 어느
학년대에 후보로 올릴지 정하는 데만 쓰고, 화면과 경고에는 측정값을 쓴다. 둘이 어긋나는 레시피는
"기하는 단순하지만 조립이 까다롭다"는 뜻이고, 그 정보는 지우지 않고 그대로 둔다.

### 개선 전략 (최대 3회)

| 걸린 항목 | 조정 |
|---|---|
| 간격·선분 길이·내각 미달 | 1.15배 확대 (A4 한계까지) → 안 되면 장식 요소 단계 축소 |
| 제작 시간 초과 | 선택 부품 제거 → 장식 단계 축소 → 0.9배 축소(간격 하한 지킴) |
| A4 초과·겹침 | 재배치 → 0.9배 축소 |
| 부품 수 초과 | 부품 수가 적은 레시피 변형으로 교체 |
| 제작 시간 초과 (적층) | 측면 띠 제거 → 장식 단계 축소 → **층 수 1 감소** → 0.9배 축소 |

3회 안에 통과하지 못하면 `failed`로 끝낸다. **임계값을 낮춰서 통과시키지 않는다.**

## 콘텐츠 2 — 드론 비행 코드

### 산출물

비행 미션(구조화된 명령 배열) + 기체별 코드(djitellopy Python 또는 블록 의사코드) + 장애물 배치도.
좌표계는 이륙 지점을 원점으로 하는 **센티미터 단위 실좌표**다 (x: 전후, y: 좌우, z: 고도).

### 기체 (`DRONE_MODELS`)

| 기체 | 명령 | 실내 | 최대 고도 | 1회 비행 |
|---|---|---|---|---|
| DJI Tello / RoboMaster TT | takeoff·land·up·down·forward·back·left·right·cw·ccw·flip | 가능 | 300cm | 300s |
| RoboLink CoDrone EDU | takeoff·land·up·down·forward·back·left·right·cw·ccw | 가능 | 200cm | 240s |
| 교육용 시뮬레이터 | 전부 | 가능 | 500cm | 무제한 |

기체가 지원하지 않는 명령이 미션에 있으면 `DRONE_UNSUPPORTED_COMMAND`(error)다.
**호환성을 "아마 될 것"으로 처리하지 않는다.**

### 장소 치수 (`VENUE_DIMENSIONS`, cm)

| 장소 | 가로 × 세로 × 천장 |
|---|---|
| 교실 | 800 × 700 × 260 |
| 강당 | 2000 × 1500 × 600 |
| 체육관 | 2800 × 1500 × 700 |
| 운동장 | 6000 × 4000 × 1000 |
| 컴퓨터실 | 700 × 600 × 250 |
| 메이커실 | 900 × 700 × 270 |

### 비행 상수 (`lib/studio/constants.ts`)

| 상수 | 값 | 근거 |
|---|---|---|
| 비행 속도 | 50cm/s | 교실·체육관에서 학생이 조종할 때 쓰는 속도. 기체 최고 속도가 아니다 |
| 회전 속도 | 90도/s | |
| 이륙 고도 | 100cm | 이륙 명령 하나로 올라가는 기본 높이 |
| 이륙 시간 | 5초 | 시동·상승·안정화 |
| 착륙 시간 | 4초 | |
| 게이트 통과 여유 | 15cm | 개구부 안쪽 기준. 벽·장애물의 50cm 와 다르다 — 통과하라고 놓은 물건이기 때문이다 |
| 학생 교대 | 60초 | 조종기 넘기고 자리 바꾸는 시간 |
| 코스 설치·정리 | 20분 | 도입·시범 포함 |

예상 소요 = `(1회 비행 시간 + 교대 60초) × 학생 수`
가용 시간 = `수업 시간 − 20분`

### 검증 항목

| 코드 | 심각도 | 무엇을 보는가 |
|---|---|---|
| `DRONE_EQUIPMENT_MISSING` | error | 보유 장비에 해당 기체가 없다 |
| `DRONE_NO_TAKEOFF` / `DRONE_NO_LAND` | error | 이륙·착륙 명령 누락 |
| `DRONE_COMMAND_AFTER_LAND` | error | 착륙 뒤에 비행 명령이 있다 |
| `DRONE_UNSUPPORTED_COMMAND` | error | 기체 미지원 명령 |
| `DRONE_VENUE_TOO_SMALL` | error | 코스 외곽이 장소에 들어가지 않는다 |
| `DRONE_OUT_OF_BOUNDS` | error | 경로가 벽 여유(50cm) 안쪽을 침범 |
| `DRONE_ALTITUDE_LIMIT` | error | 고도가 [30cm, min(천장−50cm, 기체 상한)] 밖 |
| `DRONE_OBSTACLE_CLEARANCE` | error | 경로와 장애물 간격 50cm 미달 (게이트 통과 구간은 게이트 개구부 기준) |
| `DRONE_STEP_TOO_LARGE` | error | 한 명령 이동량이 기체별 범위 밖 (하한 20cm, 상한은 기체별: Tello 500 · CoDrone 200) |
| `DRONE_TIME_OVER` | error | 1인 비행 시간 × 학생 수 > 가용 시간, 또는 1회 비행이 배터리 한계 초과 |
| `DRONE_FLIP_INDOOR` | warn | 천장 250cm 이하에서 flip |
| `DRONE_TIME_TIGHT` | warn | 가용 시간의 90% 초과 |

경로 검증은 명령을 적분해 **실제 폴리라인**을 만든 뒤 선분 단위로 본다. "대충 괜찮아 보인다"가
아니라 선분-장애물 최단거리를 계산한다.

### 안전 고정 문구 (생성물에 항상 포함, 삭제 불가)

- 사람 위로 비행하지 않는다. 비행 구역 안에 학생이 들어오지 않게 한 뒤 이륙한다.
- 프로펠러 가드를 장착한다.
- 이착륙 구역을 바닥 테이프로 표시하고 그 안에서만 띄운다.
- 조종자는 1명, 나머지는 선 밖에서 본다.

LLM이 이 문구를 지우거나 바꿔 쓰면 규칙 문구로 되돌린다.

## 성과 피드백 — 다음 생성에 쓰는 것

수업이 끝나면 강사가 **회차 단위 집계**를 입력한다.

| 입력 | 형태 |
|---|---|
| 시도 인원 / 완성 인원 | 정수 (학생 명단이 아니다) |
| 실제 소요 시간 | 분 |
| 체감 난이도 | `too_easy` / `right` / `too_hard` |
| 강사 수정 의견 | 자유 텍스트 (마스킹 통과분만 저장) |

**CRITICAL: 학생 개인 단위로 저장하지 않는다.** 완성률은 `완성 인원 / 시도 인원`이고,
누가 완성하지 못했는지는 이 플랫폼에 들어오지 않는다. 학생 개인의 수행을 기록하는 순간
"학생 개인을 진단하지 않는다"(CLAUDE.md)가 깨지고, 그 기록은 학교에서 생활기록부 근거로 쓰이려 한다.

피드백이 다음 생성에 영향을 주는 방식은 **파라미터 보정 한 가지**다.

- 같은 레시피·같은 학년대의 피드백이 **3건 이상** 모이면, 실제 소요 시간 / 예상 시간의 중위수를
  `속도 보정 계수`로 쓴다. 0.6~1.6으로 자른다.
- `too_hard`가 과반이면 난이도 상한을 1 낮춰 레시피 후보를 고른다.
- 3건 미만이면 쓰지 않는다. 한두 번의 수업이 상수를 바꾸면 안 된다 (ADR-018과 같은 이유다).

## 수업 조건 하네스 — 도안 한 장이 아니라 수업 패키지 (ADR-044)

강사가 넣는 것은 주제와 **수업 조건**이다. 나가는 것은 도안 한 장이 아니라 네 가지다.

1. **도안** — A4 1:1 SVG. 색 참고 그림(`art`)과 덧그릴 선(`trace`)
2. **학생용 사용법** — 단계마다 **실제 부품 id** 를 가리킨다. 선 그리기 → 색 고르기 → 식혀 떼어내기 → (입체면) 조립 → 마무리
3. **강사용 지도안** — 도입·안전·시범·제작·정리의 분 배분. **합이 수업 시간과 같다**
4. **검증 리포트** — 무엇이 검증됐고 무엇이 아직 아닌지

### 검색 — 결정론이고 판정기가 아니다

주제 문자열을 조회어·동의어·분류에 맞춘다 (`lib/studio/harness/retrieve.ts`). 임베딩을 쓰지 않는다.

| 찾은 방법 | 뜻 | 예 |
|---|---|---|
| `exact` | 주제 전체가 대표 단어와 같다 | "자전거" |
| `alias` | 주제 전체가 동의어와 같다 | "바이크" → 자전거 |
| `phrase` | 문장 안에 단어가 있다 (낱말 일치 포함) | "바다에 사는 물고기 모양" → 물고기 |
| `partial` | 단어 안에 주제가 있다. 약한 근거다 | "곰인" → 곰인형 |
| `tag` | 분류만 맞다. 화면에 "확인해 주세요"가 붙는다 | "바다 생물" → 거북이 |

**미적중이면 아무것도 돌려주지 않는다.** 목록의 1번을 집어 주지 않는다 — 그러면 "바다에 사는 물고기"에 가방 도안이 나간다. 미적중은 폴백 사슬(ADR-042)이 받는다.

### 사전 제작 도안 팩

`src/data/studio/pack/**` 가 들고 있는 것은 **문장과 조회어뿐이다.** 모양은 `shape_id` 로 아틀라스를 가리킨다.

- 항목마다: 조회어 · 분류 · 수업 제목 · 고른 이유 · **그릴 때 걸리는 지점** · 학습 목표
- 아틀라스에 없는 모양을 가리키는 항목은 **조용히 빠진다**
- 대표 단어와 다른 사물의 모양을 쓰면 `substitute` 이고, 화면에 "가장 가까운 ○○" 가 적힌다
- 검수: `npm run studio:pack` → 세 학년대 × 2D·3D 전수 검증 + `pack-report.md`. 하나라도 떨어지면 종료 코드 1

**주제와 같은 단어의 검수된 모양이 있으면 LLM을 부르지 않는다** (2D·대체 아님). 체험 세션의 호출이 0회가 되는 이유다.

### 검증 층 — 한 줄로 합치지 않는다

| 층 | 코드 | 심각도 | 무엇을 보는가 |
|---|---|---|---|
| 지도안 | `PLAN_PART_UNKNOWN` | error | 단계가 도안에 없는 부품을 가리킨다 |
| 지도안 | `PLAN_TIME_MISMATCH` | error | 시간 배분의 합이 수업 시간과 다르다 |
| 지도안 | `PLAN_MODE_MISMATCH` | error | 2D 산출물에 조립 지시가 섞였다 |
| 지도안 | `PLAN_STEP_EMPTY` | error | 단계에 설명이 없다 |
| 시간 | `TIME_ESTIMATE_UNVERIFIED` | warn | 제작 시간이 계산값이고 실측이 아니다 |
| 장비 | `EQUIP_PEN_COUNT_UNKNOWN` | warn | 장비 문장에서 펜 수량을 읽지 못했다 |
| 장비 | `EQUIP_PEN_SHARED` | warn | 펜 한 자루를 여럿이 나눠 쓴다 (교대 필요) |
| 장비 | `EQUIP_FILAMENT_UNCONFIRMED` | warn | 필라멘트가 입력에 없다 (없다는 뜻이 아니다) |
| 주제 | `TOPIC_SUBSTITUTED` | warn | 요청한 사물과 다른 모양이다 |
| 주제 | `TOPIC_MATCH_UNVERIFIED` | warn | 분류만 맞아서 골랐다 |
| 검색 | `RETRIEVAL_MISS` | warn | 검수된 목록에서 찾지 못했다 |

검증 상태는 **네 칸으로 따로** 나간다: `geometry`(통과/실패) · `time`(보정/추정/불명) · `topic_match`(검수됨/확인 필요) · `field`(현장 확인/미확인). 기하 통과를 "수업 검증 완료"로 적지 않는다.

### 수업 운영 상수

| 항목 | 값 | 비고 |
|---|---|---|
| 지도안 칸 (도입/안전·시범/정리) | 5 / 7 / 8분 | 합이 수업 오버헤드 20분과 같다 |
| 펜 공유 상한 | 2명 | 넘으면 교대 조와 대기 활동을 지도안에 넣는다 |
| 검색 최소 점수 | 25 | 아래는 미적중이다 |

### 알 수 없는 것은 확인 항목으로 내보낸다

콘센트·전원 · 환기와 안전 감독 · 필라멘트 보유량에는 입력 칸이 없다. 추론으로 채우지 않고 화면의 "확인이 필요한 것"에 적는다. 장비 문장에서 해석하지 못한 항목은 **원문을 그대로** 남긴다.

## 금지사항

- LLM에게 **mm·접합 규격·비행 명령·판정**을 만들게 하는 것. 이유: 검증할 수 없는 숫자가 들어오고, 그게 이 제품의 유일한 차별점을 없앤다. 윤곽은 0~1 비율로만 받고 치수는 코드가 곱한다 (ADR-036)
- 이미지 검토의 부정 판정을 `failed`로 바꾸는 것. 이유: 모델의 판정은 물리 검증이 아니다. warn으로 보여 주고 강사가 정한다 (ADR-038)
- 검증·이미지 검토를 통과하지 않은 모양을 아틀라스에 커밋하는 것. 이유: 아틀라스가 가진 값은 "검수됨" 하나다
- 검증 실패 산출물을 내려받게 하는 것. 이유: 교실에서 터지면 강사는 돌아오지 않는다
- 임계값을 통과시키려고 낮추는 것. 이유: 임계값은 물리 현상이다. 3mm는 협상 대상이 아니다
- 학생 개인 단위 성과 기록. 이유: CLAUDE.md CRITICAL — 개인화 단위는 학급(회차)이다
- 도안·코드를 학생·보호자 경로에 노출하는 것. 이유: 산출물은 강사 소유다 (ADR-019와 같은 경계)
- 서버에서 PDF를 만든다고 적는 것. 이유: 지금 PDF 라이브러리를 쓰지 않는다. 인쇄는 브라우저 인쇄(@page A4)이고 파일 내려받기는 SVG·코드 텍스트다
- 검색 미적중에서 목록의 첫 항목을 돌려주는 것. 이유: "가장 가까운"이라는 말로 엉뚱한 도안이 나간다. 미적중은 미적중이라고 말한다 (ADR-044)
- 팩 문장을 실시간 AI 응답으로 표시하는 것. 이유: 미리 써 둔 문장과 이번에 쓴 문장은 다른 것이다 (ADR-025·044)
- 실측 없이 "시간 안에 제작 가능"이라고 적는 것. 이유: 추정은 추정이라고 적어야 강사가 여유를 둔다 (ADR-044)
