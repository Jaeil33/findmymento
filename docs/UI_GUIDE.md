# UI 디자인 가이드

**방향은 "제도실"이다.** 이 제품이 내놓는 것은 글이 아니라 **A4에 1:1로 인쇄돼 교실로 들어가는 종이 한 장**이다. 그래서 화면의 색·선·글자를 도안지와 검사 성적서에서 가져온다. 라이트 단일 톤이고, 다크 테마 분기를 만들지 않는다.

학생 화면과 기관 대시보드는 같은 색·같은 컴포넌트를 쓰고, 차이는 **타이포 크기·여백·터치 타깃·모서리 반경**으로만 만든다. 테마를 2개로 나누지 않는다.

## 디자인 원칙

1. **기관·강사 화면은 도구처럼 보여야 한다.** 마케팅 랜딩이 아니라 담당자가 업무 시간에 매일 여는 화면이다.
2. **학생 화면은 3분 안에 끝나야 한다.** 한 화면에 질문 하나. 진행 상태를 항상 보여준다. 특강 직후 산만한 교실에서 휴대폰으로 쓰는 화면이다.
3. **숫자가 주인공이다.** 만족도·수요 집계는 장식 없이 크고 정확하게. 차트보다 숫자가 먼저다.
4. **색이 있으면 판정이다.** 통과는 초록, 주의는 황갈, 실패는 빨강, 포인트는 청사진 블루. 장식으로 색을 쓰지 않는다.
5. **구조가 정보다.** 선·칸·번호는 꾸미려고 넣지 않는다. 번호는 **실제로 순서일 때만** 붙인다.

| 가운데 정렬한 섹션 소개문 | 공개 랜딩도 좌측 정렬이다 (학생 모바일만 예외) |

## 타이포그래피

두 벌까지만 쓴다. 세 번째 서체(명조·모노)를 들이지 않는다.

| 역할 | 서체 |
|------|------|
| 제목·표제란·지표 숫자·워드마크 | **IBM Plex Sans KR** 600/700 — 제도 계열, 한글 전용 설계 |
| 본문·라벨·작은 숫자 | **Pretendard** — 작은 한글 가독성 |

`h1`~`h4` 는 전역 base 에서 제목 서체·700·`letter-spacing: -0.021em` 로 고정된다. 화면마다 제목 서체가 다르면 제품이 둘로 보인다.

| 용도 | 스타일 |
|------|--------|
| 랜딩 h1 | `text-[2.1rem] sm:text-[2.9rem]` |
| 섹션 제목 | `text-xl sm:text-[1.4rem]` |
| 페이지 제목 (대시보드) | `text-[1.6rem]` |
| 패널 제목 | `text-[0.95rem]` |
| 설문 질문 (학생) | `font-display text-[1.35rem]` |
| 본문 (기관) | `text-sm text-body leading-relaxed` |
| 본문 (학생·공개) | `text-base text-body leading-[1.7]` |
| 지표 숫자 | `font-display text-3xl font-bold tabular-nums` (강조 `text-4xl`) |

- 지표 숫자에는 `tabular-nums`를 반드시 넣는다. 숫자 폭이 흔들리면 표가 읽히지 않는다.
- 본문은 `word-break: keep-all` 이 전역으로 걸려 있다 — "계산합니 / 다." 같은 줄바꿈을 막는다.
- 줄 길이는 80자 아래로 둔다 (`max-w-xl`~`max-w-2xl`).

## 구조 장치 — 꾸미지 않고 정보를 싣는다

### 표제란 (`PageHeader`)
도면 표제란이다. 제목 + 조건 한 줄(`eyebrow`) + 설명 + 동작이 한 자리에 있고, 아래를 **2px 잉크선**으로 닫는다.
`eyebrow` 에는 **사실만** 넣는다 — `중등 20명 · 90분 · 교실`, `hex-box · v2`. 섹션 이름(`AI 콘텐츠 스튜디오`)을 넣지 않는다.

### 측정값 / 기준 쌍 (`MeasureRow`, 검증 결과)
이 제품의 판정 논리를 그대로 옮긴 칸이다. **"통과했습니다"보다 `7.2mm / 기준 3mm 이상` 이 근거다.**
측정값과 기준은 항상 같은 칸에서 나란히 읽혀야 한다.

### 여백 주석 (랜딩 `Band`)
섹션 제목을 왼쪽 여백에 걸고 본문을 오른쪽에 둔다. 제목 위에 라벨을 올리지 않는다.
본문이 전체 폭을 써야 하면(제품 화면 모형) `full` 로 제목을 위에 둔다.

### 모눈
종이가 주인공인 영역에만 쓴다. 장식 배경이 아니다.

## 컴포넌트

### 반경 — 기준은 "손에 쥐는가"
학생 화면만 둥글다. 강사·기관 화면은 도면 쪽에 가깝게 각을 세운다.

```
패널 · 대시보드 카드:  rounded-md  (6px)
컨트롤 · 타일 · 고지줄: rounded-sm  (4px)
배지:                 rounded-xs  (2px)
학생이 누르는 면:      rounded-xl  (12px)
선택 칩:              rounded-full
```

### 버튼
찍어 누른 자리처럼 보인다 — 각을 세우고 테두리를 가진다. 그림자로 띄우지 않는다.
```
Primary:        rounded-sm bg-point border border-point text-white hover:bg-point-hover px-4 py-2.5
Secondary:      rounded-sm bg-card border border-line-strong text-ink hover:bg-muted px-4 py-2.5
Text:           text-sub hover:text-ink hover:underline
학생 화면 전용:  w-full min-h-12 text-base  (터치 타깃 48px 이상)
```

### 입력 필드
```
기본:           rounded-sm bg-card border border-line-strong px-4 py-3 text-sm
                focus:border-point focus:ring-2 focus:ring-point/35
학생 설문 전용:  px-4 py-4 text-base  (16px 미만이면 iOS에서 포커스 시 자동 확대된다)
```
라벨·힌트 길이가 달라도 **한 줄에 놓인 입력칸의 아랫변이 맞는다** (`flex h-full flex-col` + 컨트롤 `mt-auto`). 나란히 놓인 칸이 들쭉날쭉하면 서식으로 읽히지 않는다.

### 선택 칩
```
미선택: rounded-full border-2 border-line text-body
선택:   rounded-full border-2 border-point bg-point-bg text-point font-semibold
```
테두리 두께를 두 상태에서 같게 둔다 — 고를 때 칩 크기가 흔들리면 손가락이 빗나간다.

### 고지줄 · 빈 상태
면을 깔지 않고 **왼쪽 2px 선**으로 구분한다. 빈 상태를 가운데 정렬하지 않는다 — 본문과 같은 자리에서 읽히는 쪽이 안내문답다.

## 레이아웃

- 기관·강사 화면: `max-w-6xl`, **좌측 정렬**
- 학생 화면: `max-w-md mx-auto` — 모바일 단일 컬럼이므로 중앙 배치가 유일한 예외다
- 간격: `gap-3`~`gap-4`, 섹션 간 `space-y-8`
- 좌우 여백은 어느 너비에서도 최소 16px 유지

## 애니메이션

- `fade-in` (0.2s) — 추천 결과, 모달
- `slide-up` (0.25s) — 설문 단계 전환
- 그 외 모든 애니메이션 금지. 로딩은 스피너 대신 정적 문구(`추천을 찾고 있어요`)로 처리한다.
- `prefers-reduced-motion: reduce`에서는 둘 다 끈다.

## 아이콘

- SVG 인라인, `strokeWidth 1.5`
- 아이콘을 둥근 배경 박스로 감싸지 않는다
- 아이콘 단독으로 의미를 전달하지 않는다. 항상 텍스트 라벨과 함께 쓴다

## 문구 — 화면의 절반은 글이다

1. **읽는 사람이 아는 말로 쓴다.** `산출물 검증 파이프라인` 이 아니라 `통과하지 못한 도안은 인쇄되지 않습니다`.
2. **숫자와 사물을 넣는다.** `정밀한 도안` 이 아니라 `A4 1:1`, `3mm`, `부품 6개`, `자로 재서 50mm`.
3. **버튼은 일어날 일을 그대로 적는다.** `제출` 이 아니라 `도안 만들기`, `보호자님, 문의 남기기`. 같은 동작은 흐름 끝까지 같은 이름을 쓴다.
4. **없는 기능을 적지 않는다.** 서버 PDF 생성, 결제, 1:1 메시지는 없다. 사용 방법에 적은 단계는 전부 지금 화면에 있는 것이다.
5. **실패 화면에는 다음 행동이 있다.** 무엇이 걸렸는지 + 무엇을 바꾸면 되는지.
6. 과장 금지 — 파일럿 공급 규모를 숫자로 그대로 적는다 (아래 안전규칙 5).

## 공개 디렉토리와 보호자 문의 (개인 경로)

읽는 사람은 "내 아이를 이 사람에게 보내도 되는가"를 판단하는 성인이다.

### 레이아웃
```
랜딩·헤더·푸터: max-w-6xl
디렉토리 목록:  max-w-6xl, 카드 그리드 (모바일 1열 / sm 2열 / lg 3열) — 헤더와 좌우 끝을 맞춘다
상세 페이지:    max-w-3xl — 읽는 화면이므로 본문 폭을 좁게 둔다
문의 폼:        max-w-xl
```

### 강사·프로그램 카드에 넣는 것
분야 · 프로그램 제목 · 대상 학년 · 형태(회차 수) · **지역(시군구명)** · 소속 업체명. 지역을 카드에서 빼지 마라 — 이 제품의 가치가 "우리 지역"이므로 보호자가 가장 먼저 보는 정보다.

### 넣지 않는 것
- **연락처·SNS·주소 영역을 만들지 않는다.** 조건부로 숨기는 컴포넌트도 만들지 않는다.
- **강사 개인 사진을 쓰지 않는다** (학생 추천 카드와 같은 규칙).
- 평점·리뷰·별점 UI를 만들지 않는다. MVP에 리뷰 시스템이 없으므로 빈 별이 뜨는 자리를 만들면 안 된다.
- "인기" "추천" 배지를 만들지 않는다. 순위에 과금이 반영되지 않는다는 약속과 충돌하는 인상을 준다(ADR-009).

### 빈 상태 (E-07 — 파일럿에서 과반)
`우리 동네 → 인접 지역 → 그래도 없음` 3단계를 **화면에 그대로 보여준다.** "광명시에는 아직 없어요. 가까운 구로구·시흥시에서 찾았어요" 같은 문장이 빈 결과보다 훨씬 낫다. 3단계 모두 0건이면 Q&A 유도를 가장 크게 둔다.

### 문의 폼
```
보호자 이름*      text
연락처*           tel  (휴대폰 또는 이메일)
지역*             시군구 선택
학년대*           초등 / 중등 / 고등   ← 학년 단위로 쪼개지 마라. 아이 특정에 가까워진다
관심 분야*        칩 선택
요청 내용         textarea 300자
[동의] 개인정보 수집·이용 동의*  ← 체크박스. 수집 항목·목적·보유기간을 펼쳐볼 수 있게
```

**아이 이름·학교·생년월일 입력란을 만들지 마라.** 이건 디자인 선택이 아니라 CLAUDE.md의 CRITICAL 규칙이다.

### 접수 완료 화면
"접수됐어요"로 끝내지 마라. **언제 연락이 오는지**를 본문 크기로 쓴다 — 운영자가 수동 배정하므로 즉시 연락이 아니다. 예: `영업일 2일 안에 담당 강사가 알려주신 연락처로 연락드려요.` 이 한 줄이 없으면 문의가 씹혔다고 느끼고 다시 문의한다.

## 콘텐츠 스튜디오 화면 규칙

1. **검증 결과를 도안보다 먼저 보여준다.** 도안이 먼저 보이면 강사는 통과 여부를 읽지 않고 인쇄한다 (ADR-030).
2. **라운드를 접어 두거나 요약하지 않는다.** 생성 → 검증 → 개선 → 재검증 전 과정을 그대로 보여준다. "AI가 만들어 줬다"는 근거가 못 되고, "2.4mm 미달 → 1.15배 확대 → 3.1mm 통과"는 근거가 된다.
3. **통과하지 못한 산출물에는 인쇄·내려받기 버튼을 만들지 않는다.** 미리보기는 워터마크가 찍힌 채로 보여준다.
4. **기준값을 화면에 적는다.** 무엇과 비교했는지 모르면 판정이 의미가 없다.
5. 랜딩이 보여주는 도안은 **그 요청에서 실제로 생성한 것**이고, 강사 화면과 **같은 렌더러**를 쓴다. 모양을 따로 그리면 코드가 바뀐 날부터 랜딩이 거짓말을 한다.

## 안전 관련 UI 규칙 (CRITICAL)

1. **강사 연락처를 표시하는 UI 영역을 아예 만들지 않는다.** 조건부로 숨기는 컴포넌트도 만들지 않는다. 존재하지 않는 영역은 새지 않는다.
2. **학생은 항상 가명으로 표시한다.** `중2 학생 A` 형식. 가명코드 원문을 화면에 그대로 노출하지 않는다.
3. **Q&A 작성 화면에 "이 질문은 모두에게 공개되며 기관 선생님도 봅니다"를 입력란 바로 위에 명시한다.** 작은 회색 각주로 숨기지 않는다.
4. 추천 카드에 강사 개인 사진을 쓰지 않는다. 분야·경력·프로그램 정보로만 구성한다.
5. **현재 등록된 업체 수·강사 수를 화면에 명시한다.** 파일럿 시점에는 추천 결과가 한 업체로 쏠린다. 이걸 숨기면 기관이 나중에 알아차렸을 때 데이터 전체의 신뢰를 잃는다.
6. **공개 디렉토리는 비로그인 화면이지만 학생도 볼 수 있다고 가정한다.** 따라서 "문의하기" 버튼의 문구는 보호자를 향해야 한다 — `보호자님, 문의 남기기`처럼 주체를 명시한다.
7. **보호자 문의 폼에 아이 개인정보 입력란을 만들지 않는다.** 학년대까지만.
8. **학생 설문 화면의 제목·버튼에 "만족도 조사"를 쓰지 않는다.** 학생 화면의 주제는 "나에게 맞는 다음 교육 찾기"다 (SURVEY.md 설계 원칙 7).
9. **강사 화면의 교실 투사용 QR은 전체화면 단일 요소로 만든다.** 교실 뒤에서 보인다는 기준으로 QR 최소 320px, 입장 코드는 `text-5xl tabular-nums`. 네비게이션·사이드바를 같이 띄우지 않는다.

## 접근성

- 본문 대비 4.5:1 이상. 보조 텍스트(`#576a70`)는 흰 면과 페이지 면 양쪽에서 4.5:1 을 넘는다.
- 모든 입력에 `<label>`을 연결한다. placeholder를 라벨 대신 쓰지 않는다.
- 터치 타깃 최소 44×44px. 학생 화면은 48px.
- 포커스 링은 `2px solid var(--color-point)` + `outline-offset: 2px` 전역 고정.
