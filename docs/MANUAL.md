# Find My Mento 사용 설명서

이 문서는 **화면 앞에 앉은 사람이 무엇을 하는가**를 설명한다. 코드를 띄우는 방법은 `README.md`,
흐름의 근거는 `docs/USER_FLOW.md`, 왜 그렇게 만들었는지는 `docs/ADR.md`에 있다.

읽는 사람에 따라 필요한 절이 다르다.

| 나는 | 읽을 절 |
|---|---|
| 기관·학교 담당자 | 2 · 3 · **4** · 5 · 9 · 10 |
| 강사 | 2 · 3 · 6 · 9 · 10 |
| 운영자 (서비스 관리자) | 2 · 3 · 7 · 8 · 9 · 11 · 12 |
| 처음 보는 사람 | 1 · 2 만 읽어도 된다 |

## 1. 이 서비스가 하는 일

**지역의 직업인 강사를 학교·기관·개인과 연결한다.** 대상은 초·중·고 학생이고, 파일럿 지역은 경기도 광명시다.

연결이 필요한 쪽은 셋이다.

- **학교** — 고교학점제 선택과목, 진로체험, 동아리에 넣을 **인맥 밖의 외부 강사**가 필요하다.
- **기관** — 청소년재단·수련관처럼 연간 진로사업을 돌리는 곳. 회차를 계속 열어야 한다.
- **개인(보호자)** — 아이가 특강에서 흥미를 느꼈고, 계속 배울 곳을 찾는다.

세 쪽 모두 같은 강사 풀을 본다. 다른 것은 **들어오는 문**이다.

---

## 2. 들어오는 문은 세 개다

이 서비스를 "특강 후속 교육 플랫폼"으로만 이해하기 쉬운데, 그건 **가장 강한 진입점 하나**일 뿐이다.
설문 데이터가 한 건도 없는 상태에서 기관이 곧바로 강사를 섭외하는 경로가 따로 있다.

| | 경로 A · 첫 섭외 | 경로 B · 특강→후속 | 경로 C · 개인 문의 |
|---|---|---|---|
| 시작하는 사람 | 기관·학교 담당자 | 기관·학교 담당자 | 보호자 |
| 시작 조건 | **아무것도 필요 없다** | 특강 회차 1개 | 없음 |
| 첫 화면 | `/programs` · `/org/recruitment` | `/org/sessions/new` | `/programs` |
| 하는 일 | 강사를 찾아 섭외 요청 | 특강 → 설문 → 수요 확인 → 섭외 | 디렉토리 열람 → 문의 |
| 끝나는 곳 | 강사 수락 → 첫 특강 개설 | 후속 과정 개설 | 운영자가 강사에게 배정 |
| 판단 근거 | 지역 · 분야 | **학생 응답 수치** | 보호자가 쓴 요청 |

**A와 B는 이어져 있다.** A로 처음 강사를 불러 특강을 열면, 그 특강이 B의 출발점이 된다.
B가 한 바퀴 돌면 수요 숫자가 생기고, 그 숫자가 다음 A를 훨씬 쉽게 만든다.

```
[A] 디렉토리에서 강사 발굴 → 섭외 요청 → 수락
                ↓
        첫 특강 회차 등록
                ↓
[B] QR → 학생 설문 → 리포트 → 관심 표현 → 보호자 동의 → 섭외 → 후속 과정 개설
                ↓
        후속 과정도 새 회차로 등록 → 다시 B
```

## 3. 계정과 로그인

### 3-1. 공개 회원가입이 없다

가입 버튼을 찾지 마시라. 없는 게 정상이다. 미성년자가 쓰는 서비스라 **아무나 들어와 강사 목록과 학생
수요를 볼 수 있으면 안 된다.**

| 역할 | 계정 | 만드는 법 |
|---|---|---|
| 기관 담당자 | 있음 | 운영자가 보낸 **초대 링크** |
| 학교 담당교사 | 있음 | 운영자가 보낸 **초대 링크** |
| 강사 | 있음 | 운영자가 보낸 **초대 링크** |
| 운영자 | 있음 | 최초 1명은 DB에서 직접 연결, 이후는 초대 |
| **학생** | **없음** | QR + 가명코드로만 들어온다 |
| **보호자** | **없음** | 문의 폼만 쓴다 |

### 3-2. 초대받은 사람이 하는 일

1. 메일로 받은 링크(`/invite/{토큰}`)를 연다
2. 초대받은 **그 이메일 주소**를 입력한다
3. 메일로 온 로그인 링크를 누른다 → 계정이 만들어지고 바로 대시보드로 들어간다

**비밀번호는 쓰지 않는다.** 매번 메일로 오는 링크로 로그인한다.
초대 링크는 **1회용이고 7일 뒤 만료**된다. 남에게 전달하면 그 사람이 대신 계정을 만들어 버리니 전달하지 마시라.
만료됐으면 운영자에게 재발송을 요청하면 된다.

### 3-3. 그냥 둘러보고 싶을 때 (데모 모드)

Supabase 키를 넣지 않고 띄우면 데모 데이터로 동작한다. `/login`에 역할 버튼 4개가 나온다.

| 버튼 | 보이는 화면 |
|---|---|
| 이수진 · 기관 담당자 | 광명시청소년수련관 시점 |
| 강민호 · 기관 담당자 | 광명하안중학교 — 학교 시점 |
| 박서연 · 강사 | 배정 회차 · 리포트 · 섭외 · Q&A |
| 운영자 | 심사 · 문의 배정 · 미답변 큐 |

학생 화면은 로그인 없이 바로 열린다 — `/s/735104`(응답 열림), `/s/482913`(마감된 회차).

**데모에는 잘 되는 경우만 들어 있지 않다.** 배정 강사가 없는 회차, 응답 0건 회차, 공급이 0인 분야,
48시간 미답변 질문이 일부러 섞여 있다. 화면을 검수할 때 그 상태를 그대로 보게 된다.

> 데모 모드에서 입력한 내용은 서버 메모리에만 남는다. 재시작하면 사라진다.

## 4. 경로 A — 기관·학교가 강사를 처음 섭외하기

**이 절이 "후속 교육"과 무관한 경로다.** 특강도, 설문도, 학생 응답도 하나 없이 시작할 수 있다.
학기 편성 전에 외부 강사를 찾아야 하는 진로전담 교사가 가장 많이 쓰는 길이다.

### A-1. 어떤 강사가 있는지 본다 — `/programs`

로그인 없이도 열린다. 필터 네 개로 좁힌다.

- **지역** — 수도권 66개 시·군·구가 모두 선택지에 있다. 우리 지역에 결과가 없으면 **인접 지역까지 자동으로 넓혀** 다시 찾는다. 그래도 없으면 없다고 말해 준다. 결과가 0건인 것 자체가 운영자에게는 영업 신호로 남는다.
- **분야** — 드론, 3D 모델링·프린팅, VR·AR 등
- **대상 학년** — 초 / 중 / 고
- **형태** — 단기 과정 / 1회 특강 / 동아리

카드를 누르면 프로그램 상세, 거기서 강사 상세(`/instructors/{id}`)로 간다.
**강사 연락처·SNS·주소는 어느 화면에도 없다.** 평점·리뷰·"인기" 배지도 없다. 일부러 만들지 않았다(11절).

> 대시보드에서는 `강사 찾기` 탭이 같은 화면으로 연결된다. 요약 화면 아래쪽 **"인맥 밖의 강사 찾기"**
> 패널도 같은 곳을 가리킨다.

### A-2. 섭외 요청을 보낸다 — `/org/recruitment`

`섭외` 탭을 연다. 화면 아래 **"섭외 후보"** 목록이 있다.

- 우리 지역과 **인접 2단계까지**의 **심사 완료 강사 전부**가 나온다.
- **수요 데이터가 0건이어도 나온다.** 첫 섭외를 막는 조건이 없다.
- 정렬 기준은 **수요 크기 → 거리**뿐이다. 소속 업체나 구독 여부는 순위에 반영되지 않는다.
- 우리 지역 강사에게는 `우리 지역` 배지가 붙는다.

각 후보 카드 오른쪽에 요청 폼이 있다.

| 입력 | 무엇을 적나 |
|---|---|
| **분야** | 그 강사가 맡는 분야 중 하나 |
| **수요 인원** | 수요 집계가 있으면 자동으로 채워진다. **없으면 예상 참여 인원을 직접 적는다** (예: 한 학급 28) |
| **요청 메모** | **장소 · 희망 시간대 · 대상 학년**을 반드시 적는다. 강사는 이 메모만 보고 판단한다 |

`섭외 요청 보내기`를 누르면 끝이다. 보낸 요청은 화면 위 **"보낸 요청"** 목록에 상태와 함께 남는다.

### A-3. 강사의 답을 기다린다

강사 화면에 `수락` / `거절` 버튼이 뜬다.

- **수락** — 상태가 `수락`으로 바뀐다. 일정·장소 협의로 넘어간다(A-4).
- **거절** — 거절된 요청 아래에 **같은 분야 대체 강사**가 바로 제안되고, `이 강사에게 요청` 버튼 한 번으로 재요청된다.
- **주변에 같은 분야 강사가 더 없으면** 그 건은 **미충족 수요**로 남아 `/org/demand`와 운영자 화면에 쌓인다. 이 숫자가 운영자가 새 강사를 영입하는 근거가 된다.

거절은 실패가 아니다. 강사 화면에도 "거절하셔도 괜찮습니다"라고 쓰여 있다 — 억지로 수락시키면 수업 질이
떨어지고, 그게 학교 쪽 신뢰를 깎는다.

### A-4. 수락 이후 — 지금은 사람이 이어 준다

**중요.** 수락 직후의 일정·장소 협의는 **플랫폼 밖에서 이뤄진다.**
강사 연락처는 본인과 운영자만 볼 수 있고, 기관 담당자 화면에는 나오지 않는다(설계상 그렇다).

그래서 파일럿 단계에서는 이렇게 운영한다.

1. 기관이 요청 메모에 **연락 가능한 시간대와 기관 대표번호**를 적어 둔다
2. 운영자가 `수락` 상태를 보고 양쪽을 이어 준다 (메일·전화)
3. 협의가 끝나면 기관이 회차를 등록한다 → 경로 B로 합류

### A-5. 첫 특강 회차를 만든다 — `/org/sessions/new`

여기서부터는 5절과 같다.

## 5. 경로 B — 특강에서 후속 교육까지 (기관·학교)

한 번의 특강이 후속 과정으로 이어지는 데 **약 2주**가 걸린다. 이 14일이 제품의 단위다.

| 시점 | 누가 | 무엇을 |
|---|---|---|
| D-7 | 기관·학교 | 회차 등록 + 강사 배정 + QR 발급 |
| D-3 | 기관·학교 | 학생 가명코드 발급·출력 |
| D-1 | 운영자 | 해당 분야 강사의 승인 상태 점검 |
| **D-day** | **강사** | 수업 마무리 안내 + **교실에 QR 투사** |
| D-day | 학생 | 설문 3분 → 추천 확인 → 관심 표현 또는 질문 |
| D+1 | 강사 | Q&A 답변 · 리포트 확보 → 학교에 제출 |
| D+1~3 | 기관·학교 | 리포트 확인 |
| D+3 | 기관·학교 | 관심 표현 검토 → 보호자 동의 절차 시작 |
| D+5 | 기관·학교 | 섭외 요청 발송 |
| D+7 | 강사 | 수락 → 일정 협의 |
| D+14 | 기관·학교 | 후속 과정 시작 — **이것도 새 회차로 등록** |

### 5-1. 회차 등록 — `/org/sessions/new`

`특강 회차` → `회차 만들기`.

| 입력 | 설명 |
|---|---|
| 제목 | 학생이 보는 이름. 예) 드론으로 우리 동네 찍어보기 |
| 분야 | 추천과 수요 집계의 기준이 된다 |
| 대상 학년대 | 초 / 중 / 고 |
| 진행일 | 특강 날짜 |
| **응답 마감일** | 이 날짜까지만 학생이 설문을 낼 수 있다. **보통 진행일 +5~7일** |
| 예상 학생 수 | 응답률 계산에 쓰인다 |
| **배정 강사** | 수업을 진행하는 강사 |

저장하면 **6자리 입장 코드와 QR이 자동으로 만들어진다.**

> **배정 강사를 비워 두지 마시라.** 배정하지 않으면 강사가 교실에서 QR을 띄울 수도, 리포트를 볼 수도
> 없다. 대시보드 "확인이 필요한 회차"에 경고로 뜬다.

### 5-2. 학생 가명코드 발급 — `/org/sessions/{id}/codes`

학생은 이름을 쓰지 않는다. 대신 **6자리 가명코드**를 받는다.

1. 학년과 발급 수를 입력해 발급한다 (예: 2학년 30개)
2. 인쇄해서 **스티커 / 명찰 / 좌석표**로 수업 전에 나눠 준다
3. 어느 코드가 누구인지는 **기관만 안다.** 플랫폼은 모른다

코드를 못 나눠 줬어도 괜찮다. 학생은 설문 첫 화면에서 **"익명으로 하기"**를 고를 수 있다.
다만 익명 응답은 나중에 개별 후속 안내로 연결되지 않는다.

### 5-3. 강사에게 미리 부탁할 것

학생 유입의 실제 트리거는 교실 벽의 포스터가 아니라 **강사의 마지막 한마디**다.
강사 대시보드 맨 위에 "수업 마무리 안내" 문구가 준비돼 있다. 강사에게 **수업 끝 3분을 비워 달라고**
미리 부탁해 두는 것이 응답률을 가장 크게 바꾼다.

### 5-4. 특강 당일 — 교실에서

1. 강사(또는 담당자)가 **`/project/{회차ID}`**를 프로젝터에 띄운다. 전체화면 QR이다
2. 학생이 휴대폰으로 스캔 → `/s/735104` 같은 주소가 열린다
3. QR을 못 찍는 학생을 위해 화면의 **6자리 숫자**를 읽어 준다

> **반드시 리허설하시라.** 실물 휴대폰으로, **교실 뒤쪽 좌석에서** 찍어 본다.
> QR이 잘못된 도메인을 가리키면 그날 교실의 QR이 전부 죽는다.

### 5-5. 학생이 하는 3분 — `/s/{입장코드}`

| 순서 | 질문 | 필수 |
|---|---|---|
| 1 | 가명코드 6자리 입력 (또는 익명) | 필수 |
| 2 | 학년 | 필수 |
| 3 | 오늘 수업 만족도 | 필수 |
| 4 | **더 배우고 싶은 마음 (후속 의향)** | 필수 |
| 5 | 관심 분야 | 필수 |
| 6~8 | 무엇을 해 보고 싶은지 · 관련 직업 · 가능한 시간대 | **선택** |

**후속 의향이 낮으면 6~8번을 묻지 않는다.** 관심 없는 학생을 붙잡아 두지 않는다.

제출하면 **추천 카드**가 나온다. 지역·분야·학년으로 후보를 거른 뒤 AI가 순위를 매긴 결과다.

- 마음에 드는 카드에서 **"더 배우고 싶어요"** → 관심 표현이 **기관 담당자에게** 간다
- 추천이 0건이거나 더 궁금하면 → **공개 Q&A로 질문**

**학생이 누르는 버튼 중 강사에게 직접 닿는 것은 하나도 없다.** 관심 표현은 전부 기관을 거친다.

### 5-6. 리포트 확인 — `/org/sessions/{id}`

다음 날부터 본다.

- 응답 수 / 응답률 (예상 학생 수 대비)
- 만족도 분포
- **후속 의향 분포** ← 가장 중요하다
- 분야 × 학년대 관심
- 미충족 수요 (관심은 있는데 주변에 강사가 없는 분야)

이 리포트는 **그대로 내부 보고에 쓸 수 있게** 만들어져 있다. 배정된 강사도 자기 회차의 같은 리포트를 본다.

### 5-7. 관심 표현 검토 — `/org/interests`

학생이 "더 배우고 싶어요"를 누른 건이 여기 모인다. **강사에게는 아직 아무것도 전달되지 않았다.**

1. 건별로 **승인 / 반려**를 고른다
2. 승인한 건은 **보호자 동의**를 받는다 — 종이·문자·알림장 등 **기관이 원래 쓰던 방법**으로
3. 회수한 동의를 화면에 **기록**한다 (동의 방법 선택)

플랫폼은 동의를 **대신 받지 않는다.** 보호자 계정을 만들면 동의율이 그 가입률에 묶여 버리기 때문에
일부러 기록만 한다.

### 5-8. 섭외 요청 → 후속 과정 개설

동의가 회수되면 `/org/recruitment`에서 요청을 보낸다. **A-2와 같은 화면**이다.
다른 점은 하나 — 이번에는 수요 인원이 **학생 응답에서 나온 실제 숫자**로 자동으로 채워진다.

강사가 수락하면 일정을 협의하고, 후속 과정을 **새 회차로 등록**한다. 그러면 그 과정도 QR·설문·리포트를
갖게 되고 다시 5-1로 돌아간다.

### 5-9. 수요 화면 — `/org/demand`

여러 회차의 응답이 분야 × 학년대로 쌓인 곳이다.

- **미충족 수요** — 관심은 있는데 우리 지역·인접 지역에 강사가 없는 분야. 운영자가 이 숫자로 새 강사를 찾는다
- **분야 × 학년대** — 후속 의향 3점 이상만 센 숫자가 실제 수요다
- **"아직 잘 모르겠어요"** — 분야를 고르지 못한 응답. 버리지 않고 따로 센다. 탐색 기회가 더 필요한 집단이다

다음 해 사업계획서에 그대로 붙일 수 있는 숫자다.

## 6. 강사가 하는 일

강사는 **회차를 직접 만들 수 없다.** 기관·학교가 만들고 강사를 배정한다. 이건 제약이 아니라 역할 분담이다 —
학교 행사를 외부인이 마음대로 열 수는 없기 때문이다.

### 6-1. 프로필 — `/instructor/profile`

보호자·기관이 보는 공개 정보다. 심사 상태, 공개 정보, 등록된 프로그램을 확인한다.

**MVP에서는 프로필·프로그램 등록을 운영자가 대행한다.** 고칠 내용이 있으면 운영자에게 알린다.
프로필과 프로그램 설명이 구체적일수록 **디렉토리에서 발견되고 보호자 문의가 배정될 가능성이 높아진다.**

내 연락처는 **어느 공개 화면에도 표시되지 않는다.** 보호자 문의는 운영자를 거쳐 리드로 전달된다.

### 6-2. 배정 회차 — `/instructor/sessions`

기관이 나를 배정한 회차만 보인다. 회차를 열면:

- **입장 QR** — 수업 마지막에 이 화면을 프로젝터에 띄운다
- **회차 리포트** — 다음 날 확인한다. **학교·기관에 제출할 수 있는 집계 자료**다

리포트를 제출하는 강사와 그러지 않는 강사는 재섭외율이 다르다. 이게 강사에게 가장 실질적인 도구다.

### 6-3. 섭외 요청 — `/instructor/recruitment`

기관·학교가 보낸 과정 개설 요청이다. 기관명·지역·분야·수요 인원·요청 메모를 보고 **수락 또는 거절**한다.
거절해도 불이익이 없다. 기관에는 같은 분야의 다른 강사가 바로 제안된다.

### 6-4. Q&A 답변 — `/instructor/qna`

내 분야의 학생 질문이 온다. **답변은 모두에게 공개**되고 기관 담당자도 함께 본다.
1:1 비공개 메시지는 없다. **48시간 넘게 답이 없으면 운영자 큐에 올라간다.**

답변에 연락처·SNS·외부 링크를 쓰면 자동으로 가려진다. 질문한 학생 한 명이 아니라 **같은 질문을 가진
모든 학생에게 답한다**고 생각하고 쓰면 된다.

### 6-5. 문의 리드 — `/instructor/leads`

보호자가 공개 디렉토리에서 남긴 문의 중 **운영자가 나에게 배정한 건**이다.
보호자 이름·연락처·지역·학년대·관심 분야·요청 내용이 보인다. **알려 준 연락처로 직접 연락하면 된다.**

아이 이름·학교·생년월일은 애초에 받지 않으므로 보이지 않는다.

### 6-6. 지역 수요 — `/instructor/demand`

내 활동 지역에 지금 어떤 분야의 수요가 있는지 본다. 어떤 프로그램을 새로 만들지 판단하는 데 쓴다.

## 7. 보호자가 하는 일 (경로 C)

보호자는 **계정을 만들지 않는다.** 로그인도 마이페이지도 없다. 보통 한 번 쓰고 끝난다.

1. `/programs`에서 지역·분야·학년으로 프로그램을 찾는다
2. 프로그램·강사 상세를 본다 (연락처는 없다)
3. `/inquiry`에서 문의를 남긴다

| 입력 | 필수 |
|---|---|
| 보호자 이름 | 필수 |
| 연락처 (휴대폰 또는 이메일) | 필수 |
| 지역 | 필수 |
| **아이 학년대 (초/중/고)** | 필수 |
| 관심 분야 | 필수 |
| 요청 내용 (시간대·궁금한 점) | 선택 |
| 개인정보 수집·이용 동의 | 필수 |

**아이 이름·학교·생년월일 입력란이 없다.** 학년대까지만 받는다. 아이를 특정할 수 있는 정보를 애초에
받지 않는 것이 이 서비스의 전제다.

접수되면 운영자가 지역·분야에 맞는 심사 완료 강사에게 배정하고, **영업일 2일 안에** 강사가 연락한다.

## 8. 운영자의 하루 10분

`/admin` 요약 화면에 **지금 사람 손이 필요한 일만** 모여 있다.

### 8-1. 강사 심사 — `/admin/instructors`

승인 전에는 추천·디렉토리·Q&A **어디에도 노출되지 않는다.**

- 자격 증빙 확인
- **성범죄경력 조회 증빙 확인 — 이게 없으면 승인할 수 없다**
- 증빙 파일은 비공개 버킷에 있고, 화면에는 확인 여부만 표시된다

반려·중지된 강사는 노출되지 않으며, 사유가 해소되면 복구할 수 있다.

### 8-2. 초대·계정 — `/admin/invitations`

기관 담당자·학교 교사·강사·운영자 계정을 여기서만 만든다. 토큰은 **1회용이고 7일 만료**다.
이직한 담당자는 **삭제하지 않고 접근을 차단**한다 — 그가 남긴 기록은 보존해야 하기 때문이다.

### 8-3. 보호자 문의 배정 — `/admin/inquiries`

접수 순으로 쌓인다. 지역·분야가 맞는 **심사 완료 강사**에게 배정한다. 스팸·광고는 반려한다.
강사가 리드를 확인하면 전달 완료로 표시한다. **보호자에게는 영업일 2일 안에 연락한다고 안내돼 있다.**

### 8-4. 미답변 큐 — `/admin/qna`

**48시간 넘게 답이 없는 질문**이 올라온다. 해당 분야 강사에게 직접 알리거나, 그 분야를 맡을 강사가 아예
없다면 그것이 미충족 수요 신호다.

### 8-5. 미충족 수요 = 영업 큐 — `/admin` 하단

관심은 있었지만 주변에 강사가 없어 연결되지 않은 건이다.
**이 표가 곧 신규 강사·업체 영입 제안 자료다.** "광명에 중학생 대상 VR 수요가 N명 확인됐습니다"로
시작하는 제안은 거절당하기 어렵다.

## 10. 막혔을 때

| 증상 | 원인과 해결 |
|---|---|
| 회차를 만들었는데 강사가 QR·리포트를 못 본다 | **배정 강사가 비어 있다.** 회차 상세에서 강사를 배정한다 |
| 학생이 "이 코드로는 들어갈 수 없어요"를 본다 | 입장 코드를 잘못 읽었다. 투사 화면의 6자리를 다시 읽어 준다 |
| 학생이 "응답 기간이 끝났어요"를 본다 | 응답 마감일이 지났다. 의도된 화면이다. 다음 회차부터 마감일을 진행일 +5~7일로 잡는다 |
| 응답이 0건이다 | 대부분 **QR을 띄우지 않았거나 마무리 안내를 안 한 것**이다. 강사와 마지막 3분을 다시 합의한다 |
| 학생에게 추천이 0건으로 나온다 | 그 분야 강사가 주변에 없다. 학생은 Q&A로 안내되고, 건은 **미충족 수요**로 기록된다 |
| 섭외 후보가 비어 있다 | 인접 2단계 안에 승인된 강사가 없다. 운영자에게 영입을 요청한다 |
| 강사가 요청을 거절했다 | 거절 카드 아래 **대체 강사 재요청 버튼**을 쓴다. 후보가 없으면 미충족 수요로 남는다 |
| 초대 링크가 만료됐다 | 7일이 지났다. 운영자에게 재발송을 요청한다 |
| 강사 연락처가 안 보인다 | **의도된 설계다.** 운영자를 통한다 |
| 데모에서 입력한 게 사라졌다 | 데모 모드의 쓰기는 서버 메모리에만 남는다. 재시작하면 사라진다 |

## 11. 일부러 만들지 않은 것

아래는 빠진 기능이 아니라 **이 서비스가 성립하기 위한 조건**이다. "왜 없냐"는 질문이 나오면 이 표를 보여
주면 된다.

| 없는 것 | 이유 |
|---|---|
| 학생 실명·연락처·학교 저장 | 학생 식별은 기관이 발급한 가명코드뿐이다. 유출될 데이터를 애초에 갖지 않는다 |
| 강사 연락처 표시 UI | 조건부로 숨기는 컴포넌트조차 없다. **존재하지 않는 영역은 새지 않는다** |
| 학생↔강사 1:1 비공개 메시지 | 소통은 기관이 함께 보는 **공개 Q&A**뿐이다 |
| 공개 회원가입 | 모든 계정은 1회용·만료 검증을 거친 초대에서 출발한다 |
| 학생이 강사에게 직접 닿는 버튼 | 관심 표현은 전부 기관을 거친다 |
| 보호자 문의의 아이 이름·학교·생년월일 | 학년대까지만 받는다 |
| 강사의 회차 생성 권한 | 회차는 기관·학교가 만들고 강사를 배정한다 |
| 평점·리뷰·"인기"·"추천" 배지 | 지역 강사 소수 풀에서 평점은 신호가 아니라 낙인이 된다 |
| 보호자 계정·마이페이지 | 동의율이 포털 가입률에 묶이는 것을 피한다 |

이 규칙들은 테스트(`tests/safety-invariants.test.ts`, `tests/rls-policies.test.ts`)가 소스와 DB
마이그레이션을 훑어 고정한다. 새 화면을 만들다 규칙을 넘기면 테스트가 먼저 실패한다.

## 12. 플랫폼 밖에서 사람이 해야 하는 일

기능으로 만들지 않았거나, 만들면 안 되는 일이다. 파일럿 전에 정리돼 있어야 한다.

- **섭외 수락 후 연락 중개** — 운영자가 기관과 강사를 이어 준다 (A-4)
- **보호자 동의 회수** — 기관의 기존 절차(종이·문자·알림장). 플랫폼은 기록만 한다
- **강사 증빙 수집** — 자격 + **성범죄경력 조회**. 업체 경유
- **가명코드 배부 방식 결정** — 스티커 / 명찰 / 좌석표 중 하나
- **강사용 수업 마무리 안내 스크립트 1장** — 학생 유입의 실제 트리거
- **기관 개인정보 처리위탁 계약** — **가명코드↔실명 매핑은 기관이 보유**한다는 점을 명시
